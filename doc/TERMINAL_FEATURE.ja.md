# ターミナル

[English](TERMINAL_FEATURE.md) \| 日本語

XeFM が実行するものの中には、ターミナルが必要なものがあります。サブシェル（`subshell`、**Tools → Subshell Here**）と、`vim`、`less`、REPL のように画面を描いたりキーボードを読んだりするプログラムです。XeFM がそれらにターミナルを用意する方法は、XeFM の動かし方によって変わります。

- **ターミナルで**動かしている場合、XeFM は自分が動いているターミナルを渡し、プログラムが終了するまで待ってから、ペインを読み直します。
- **デスクトップアプリ**では、XeFM はウィンドウの中に自分のターミナルを持っています。シェルやプログラムはそれぞれ、そこで*ターミナルセッション*として、専用の*画面*で動きます。その画面を離れても、セッションは動き続けます。

## どのコマンドにターミナルが渡されるか

`TEXT_EDITOR`、`TEXT_DIFF`、`FILE_ASSOCIATIONS` の `open`・`view`・`edit` のコマンド、`PROGRAMS` のエントリは、どれも同じ書き方で指定できます。

```python
TEXT_EDITOR = {'command': 'vim', 'terminal': True}
TEXT_DIFF = {'command': ['code', '--diff', '--wait'], 'terminal': False}
{'pattern': '*.log', 'view': {'command': ['less'], 'terminal': True}},
{'name': 'Python REPL', 'command': ['python3'], 'terminal': True},
```

| 指定 | ターミナルでは | デスクトップアプリでは |
|---|---|---|
| `'terminal': True` | ターミナルを渡し、XeFM は待つ | ターミナルセッションで動く |
| `'terminal': False` | バックグラウンドで動き、出力はログペインに出る | 同じ |
| 指定なし（文字列やリストのまま） | ターミナルを渡し、XeFM は待つ | バックグラウンドで動き、出力はログペインに出る |

指定のない `PROGRAMS` のエントリは、これまでどおりどちらのモードでもバックグラウンドで動きます。これらの設定項目のその他の部分は、[外部プログラム](EXTERNAL_PROGRAMS_FEATURE.ja.md)と[ファイルの関連付け](FILE_ASSOCIATIONS_FEATURE.ja.md)を参照してください。

バックグラウンドのプログラムを XeFM が待つことはありません。エラーで終了した場合は、ログペインにそう表示されます。エディターのように XeFM の終了後も動き続けるプログラムは、XeFM が終了しても止まりません。

## デスクトップアプリでは：ターミナルセッションと画面

**Subshell Here** は、アクティブなペインのディレクトリでシェルを起動し、XeFM のターミナルとしてペインの上に表示します。`'terminal': True` を指定したプログラムも同じように開きます。どれもターミナルセッションで、それぞれ専用の画面に表示されます。

*画面*とは、ウィンドウ全体に表示されるもののことです。ファイルマネージャーの画面（ペイン）と、各セッションの画面があります。画面は、その上で開いたものを保ちます。ペインの上で開いたビューアーは、ターミナルから戻ってきてもそのまま残っているので、2 つの画面を切り替えて、ファイルとターミナルを交互に見比べられます。

- **Tools → Screens…**（`screens`。ビューアーの上でも使えます。セッションの中からは `terminal.screens`）で**切り替えます**。一覧には、ファイルマネージャーの画面、各セッションの画面、そしてアクティブなペインのディレクトリで別のシェルを起動する最後の行があります。各行には、その画面に何があるかが表示されます。セッションなら実行中のコマンド（プログラムが自分に付けたタイトル。端末のタブに出るものと同じです）と、シェルが今いるディレクトリ（`make test - ~/src`。プロンプトでは `zsh - ~/src`）、ファイルマネージャーならペインの上で開いているビューアー（`File manager - viewing notes.txt`）です。今いる画面が先頭に、ほかは最後に使った順に並び、カーソルは直前にいた画面にあるので、`Enter` でそこに戻れます。離れたセッションは動き続けます。ファイルマネージャーに戻ると、ペインはディレクトリを読み直します。削除キー（`remove_list_item`）はハイライト中のセッションを終わらせます。
- **終わるとき。** シェルで `exit` するか、プログラムが終了すると、表示中かどうかにかかわらず、セッションは閉じて直前にいた画面に戻ります。失敗したシェルやプログラムは、読めるように最後の画面を残します。シェルの場合は `Enter` でもう一度起動し、`Esc` でペインに戻ります。プログラムの場合は `Enter` か `Esc` で閉じます。
- 動いている間に `terminal.close` で**閉じる**こともできます。そこで動いているものが止まるので、XeFM は先に確認します。
- **XeFM を終了する**ときに確認が出るのは、作業中のセッションがある場合だけです。作業中とは、プログラムが動いている場合と、シェルがコマンドを実行している場合です。プロンプトで待っているシェルは、そのまま終了します。

キーは[キーマッププリセット](KEYMAP_PRESETS_FEATURE.ja.md#すべてのキーの一覧)にあります。

XeFM のターミナルは libghostty で動いており、macOS と Windows のアプリには libghostty が含まれています。pip でインストールした XeFM には libghostty がないため、そのデスクトップアプリにはターミナルがありません。サブシェルやターミナル向けのプログラムは起動せず、ログにその理由が表示されます。それらを使うときは、XeFM をターミナルで（`--backend vt`）動かしてください。

### シェルの環境

XeFM が起動したシェルには、ペインのディレクトリと選択項目を表す `XEFM_*` 変数、`XEFM_ACTIVE`、`[XeFM]` プロンプトマーカーが設定されます（[ユーザーガイド：サブシェル](XEFM_USER_GUIDE.ja.md#サブシェル)を参照）。これらの変数が表すのは、シェルが起動した時点のペインです。しばらく使い続けるセッションでは、代わりに [`xefmctl`](#シェルから-xefm-に問い合わせる) で問い合わせてください。

zsh と bash 4.4 以降（macOS 標準の bash は 3.2）を起動するとき、XeFM は数行のシェル統合を追加します。これで、シェルがプロンプトで待っているときと、コマンドが終わったときがわかります。自分の起動ファイルはこれまでどおり実行されます。

### 隠れているセッションからの知らせ

セッションが隠れている間、ステータスバーには対応が必要なことが表示されます。10 秒以上かかったコマンドが終了または失敗したとき、プログラムが失敗したとき、そしてプログラムが通知（OSC 9 または OSC 777）を送ったときです。Claude Code などのツールは通知を送れます。進捗を報告するプログラム（OSC 9;4）の進捗もそこに表示されます。クリックするとそのセッションに戻ります。

シェル統合は、セッションで実行中のコマンドラインも切り替えの一覧に伝えます。シェル統合がなくても、macOS と Linux ではそこで動いているプログラムの名前が表示され、Windows ではプログラムが設定したタイトルが表示されます。

## ターミナルでは

ターミナルで動く XeFM は、自分の中にもう 1 つターミナルを描くことはしません。サブシェルやターミナル向けのプログラムには XeFM が動いているターミナルが渡され、それらが終了すると XeFM に戻ります。ターミナルセッションも切り替える画面もないので、**Screens** はメニューにもコマンドパレットにもありません。

2 つのモードの違いはこの 1 点です。デスクトップアプリはシェルをペインの裏で動かし続けられますが、ターミナルで動く XeFM にはできません。ターミナルで並行して作業するには、ターミナルのタブやウィンドウ、または tmux を使ってください。XeFM から別のターミナルウィンドウを開くには、`PROGRAMS` にそのエントリを追加します。設定ファイルのテンプレートに、Terminal.app、iTerm、Windows Terminal、tmux の例があります。

## シェルから XeFM に問い合わせる

XeFM が起動したシェル（サブシェル、ターミナルセッション、`PROGRAMS` のエントリ）では、`xefmctl` コマンドで、その XeFM の実行した時点での状態を問い合わせられます。`xefmctl` が操作するのは、その XeFM のファイルマネージャーです。ペインについてのコマンドは 1 語、それ以外についてのコマンドは名詞と動詞の 2 語です。

| コマンド | 動作 |
|---|---|
| `xefmctl selected` | 選択項目のフルパスを 1 行に 1 つずつ表示（`-0`：`xargs -0` 用に NUL で区切る） |
| `xefmctl focused` | カーソル位置の項目のフルパスを表示 |
| `xefmctl pwd` | ペインのディレクトリを表示 |
| `xefmctl cd [PATH]` | ペインを `PATH`（シェルのディレクトリからの相対パス）に移動。`PATH` を省くとシェルのディレクトリに移動。ファイルを指定すると、そのフォルダーに移動してカーソルをそのファイルに置く |
| `xefmctl view FILE` | `FILE` を XeFM のビューアーでペインの上に開き、ファイルマネージャーに切り替える。**Screens** でターミナルに戻れば見比べられる |
| `xefmctl screen list` | 画面を一覧表示。今の画面（`*`）が先頭で、それぞれに ID がつく |
| `xefmctl screen switch ID` | 画面 `ID` に切り替える。ファイルマネージャーは `files`、セッションはその番号 |
| `xefmctl session list` | ターミナルセッションを一覧表示。`*` は自分がいるセッション |

ペインは `--pane this`（既定。アクティブなペイン）、`--pane other`、`--pane left`、`--pane right` で選びます。例：

```sh
cp $(xefmctl selected) /tmp           # names without spaces
xefmctl selected -0 | xargs -0 du -sh
xefmctl cd .                          # bring the active pane to this shell's directory
xefmctl view build.log
```

シェルを起動した XeFM が終了している場合は、コマンドがそう表示します。ターミナルでサブシェルが動いている間は XeFM がその終了を待っているため、そこで使えるのは読み取るコマンド（`selected`、`focused`、`pwd`、`screen list`、`session list`）だけです。

## `TERMINAL` 設定項目

以前のバージョンは、デスクトップアプリで使うターミナルアプリを選ぶために `config.py` の `TERMINAL` を読んでいました。今はそれらを XeFM 自身のターミナルが動かすので、`TERMINAL` はもう使われません。まだ設定している config を読み込むと、XeFM が一度そう表示します。XeFM から自分のターミナルアプリを開くには、`PROGRAMS` にそのエントリを追加してください。
