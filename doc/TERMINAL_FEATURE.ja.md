# ターミナル

[English](TERMINAL_FEATURE.md) \| 日本語

XeFM が実行するものの中には、ターミナルが必要なものがあります。サブシェル（`subshell`、**Tools → Terminal**。ターミナルでは **Subshell Here**）と、`vim`、`less`、REPL のように画面を描いたりキーボードを読んだりするプログラムです。XeFM がそれらにターミナルを用意する方法は、XeFM の動かし方によって変わります。

- **ターミナルで**動かしている場合、XeFM は自分が動いているターミナルを渡し、プログラムが終了するまで待ってから、ペインを読み直します。
- **デスクトップアプリ**では、XeFM はウィンドウの中に自分のターミナルを持っています。シェルやプログラムはそれぞれ、そこで*ターミナルセッション*として、専用の*画面*で動きます。その画面を離れても、セッションは動き続けます。

## どのコマンドにターミナルが渡されるか

`TEXT_EDITOR`、`TEXT_DIFF`、`FILE_ASSOCIATIONS` の `open`・`view`・`edit` のコマンド、`PROGRAMS` のエントリは、どれも同じ書き方で指定できます。

```python
TEXT_EDITOR = {'command': 'vim', 'terminal': True}
TEXT_DIFF = {'command': ['code', '--diff', '--wait'], 'terminal': False}
{'pattern': '*.log', 'view': {'command': ['less'], 'terminal': True}},
{'name': 'Python REPL', 'command': ['python3'], 'terminal': True},
```

| 指定 | ターミナルでは | デスクトップアプリでは |
|---|---|---|
| `'terminal': True` | ターミナルを渡し、XeFM は待つ | ターミナルセッションで動く |
| `'terminal': False` | バックグラウンドで動き、出力はログペインに出る | 同じ |
| 指定なし（文字列やリストのまま） | ターミナルを渡し、XeFM は待つ | バックグラウンドで動き、出力はログペインに出る |

指定のない `PROGRAMS` のエントリは、これまでどおりどちらのモードでもバックグラウンドで動きます。これらの設定項目のその他の部分は、[外部プログラム](EXTERNAL_PROGRAMS_FEATURE.ja.md)と[ファイルの関連付け](FILE_ASSOCIATIONS_FEATURE.ja.md)を参照してください。

バックグラウンドのプログラムを XeFM が待つことはありません。エラーで終了した場合は、ログペインにそう表示されます。エディターのように XeFM の終了後も動き続けるプログラムは、XeFM が終了しても止まりません。

## デスクトップアプリでは：ターミナルセッションと画面

**Tools → Terminal**（`subshell`）は、アクティブなペインのディレクトリでシェルを起動し、XeFM のターミナルとしてペインの上に表示します。`'terminal': True` を指定したプログラムも同じように開きます。どれもターミナルセッションで、それぞれ専用の画面に表示されます。

*画面*とは、ウィンドウ全体に表示されるもののことです。ファイルマネージャーの画面（ペイン）と、各セッションの画面があります。画面は、その上で開いたものを保ちます。ペインの上で開いたビューアーは、ターミナルから戻ってきてもそのまま残っているので、2 つの画面を切り替えて、ファイルとターミナルを交互に見比べられます。

各セッションの画面は、ファイルマネージャーの画面の後ろに並ぶウィンドウのタブです。シェル、ターミナル向けのプログラム、[AI エージェント](AI_AGENT_SESSIONS_FEATURE.ja.md)が 1 本のタブバーに並びます。セッションに戻るのは 1 キーで済み、別のセッションを起動するのは意図して行う別の操作です。そのため、ペインの裏でセッションが知らないうちに増えていくことはありません。

- **画面の枠。** セッションの画面でも、ウィンドウのメニューバー（ターミナルのようにウィンドウの中にある場合）、タブバー、ステータスバーが、ファイルマネージャーと同じ位置に表示されます。変わるのはその間だけです。ステータスバーには、そのセッションで使えるキーが表示されます。ファイルマネージャーに対して働くメニュー項目は、セッションを表示している間は無効になります。
- **タブ。** セッションがある間は、ファイルマネージャーの画面も含めて、どの画面でもメニューバーの下にタブバーが表示されます。先頭が **Files**、続いてセッションごとに 1 つのタブが起動した順に並び、表示中のものが前面に出ます。各タブの先頭には表示しているものの種類（`▤` はファイルマネージャー、`$` はシェル、`>` はターミナル向けのプログラム、`✦` は AI エージェント）が出ます。セッションのタブにマウスポインターを乗せている間は末尾に `×` が表示され、`×` でそのセッションを閉じます（何かが止まる場合だけ先に確認します）。タブをクリックするとそこに移動します。`terminal.next_tab` と `terminal.prev_tab` でも移動できます。タブを横にドラッグすると並べ替えられます。移動先には縦線が表示され、ボタンを離すとそこに移ります（`terminal.move_tab_left` と `terminal.move_tab_right` でも並べ替えられます）。**Files** は先頭のままです。セッションがあなたの対応を待っているタブは、アイコンの代わりに `⚠` を、最後に見たあと何かを終えたタブは `✓` を表示します。
- **セッションに戻る。** **Terminal**（`subshell`）は、最後に使ったターミナルセッションに戻ります。シェルを起動するのは、セッションが 1 つもないときだけです。**AI Agent**（`agent`）は、AI エージェントのセッションについて同じことをします。**Switch Screen**（`switch_screen`。セッションの中からは `terminal.switch_screen`）は、ファイルマネージャーからは最後に使った画面に、どのセッションからもファイルマネージャーに移動します。セッションがまだなければシェル（ターミナルではサブシェル）を起動します。AI エージェントは起動しません。AI エージェントを起動するのは `agent` だけです。離れたセッションは動き続けます。ファイルマネージャーに戻ると、ペインはディレクトリを読み直します。
- **別のセッションを起動する。** タブの後ろの `+`（セッションの中からは `terminal.new`）で、シェルか AI エージェントのセッションを起動します。選べるものが複数あるときは、どれを起動するかを尋ねます。**New Shell Here**（`new_shell`）や **New AI Agent Here**（`new_agent`）は、セッションが開いていても新しく起動します。ディレクトリのコンテキストメニューの **Subshell Here** は、そのディレクトリで新しいシェルを起動します。
- **Screens。** **Tools → Screens…**（`screens`。ビューアーの上でも使えます。セッションの中からは `terminal.screens`）は、すべてのセッションを一覧にし、移動、終了、名前の変更、再開ができます。各行には、セッションで実行中のもの（プログラムが自分に付けたタイトル。端末のタブに出るものと同じです）と、シェルが今いるディレクトリ（`make test - ~/src`。プロンプトでは `zsh - ~/src`）が表示され、右側に種類、状態、最後に使った時刻が出ます。対応を待っているものが先頭に、ほかは最後に使った順に並びます。カーソルは、表示中のものを除いて最後に使ったセッションにあります。その下には、作業の途中ではないセッションをまとめて閉じる **Close N idle sessions**、[閉じた AI の会話](AI_AGENT_SESSIONS_FEATURE.ja.md#閉じても失わない)、アクティブなペインのディレクトリで新しいシェルや AI エージェントのセッションを起動する行が並びます。削除キー（`remove_list_item`）はハイライト中のセッションを閉じ、名前の変更キー（`rename_list_item`）はそのセッションに自分で名前を付けます。付けた名前はタブにも表示されます。
- **終わるとき。** シェルで `exit` するか、プログラムが終了すると、表示中かどうかにかかわらず、セッションは閉じ、隣のタブ（後ろのタブ、なければ前のタブ。最初のセッションならファイルマネージャー）が表示されます。cmd の `exit` のように、それまでのコマンドのエラーを引き継いで終わる場合でも、`exit` でシェルは閉じます。失敗したプログラムと、何も入力しないうちに終わったシェル（起動できなかった場合）は、読めるように最後の画面を残します。`Enter` か `Esc` で閉じます。シェルをもう一度起動するには、新しく開いてください（**New Shell Here**）。
- `terminal.close` で**閉じます**。XeFM が先に確認するのは、閉じると何かが止まる場合だけです。プログラムが動いている場合と、シェルがコマンドを実行している場合です。プロンプトで待っているシェルは、そのまま閉じます。
- **XeFM を終了する**ときに確認が出るのは、作業中のセッションがある場合だけです。作業中とは、プログラムが動いている場合と、シェルがコマンドを実行している場合です。プロンプトで待っているシェルは、そのまま終了します。

キーは[キーマッププリセット](KEYMAP_PRESETS_FEATURE.ja.md#すべてのキーの一覧)にあります。

XeFM のターミナルは libghostty で動いており、macOS と Windows のアプリには libghostty が含まれています。pip でインストールした XeFM には libghostty がないため、そのデスクトップアプリにはターミナルがありません。サブシェルやターミナル向けのプログラムは起動せず、ログにその理由が表示されます。それらを使うときは、XeFM をターミナルで（`--backend vt`）動かしてください。

### 選択、コピー、貼り付け

ドラッグするとテキストを選択します。ダブルクリックで単語を、トリプルクリックで行を選択し、`Alt` を押しながらドラッグすると矩形で選択します。マウスを自分で使うプログラム（vim、htop など）では、`Shift` を押しながらドラッグしてください。

| | どのシステムでも | macOS | Windows ではさらに |
|---|---|---|---|
| 選択範囲をコピー | `Ctrl+Shift+C`、`Ctrl+Insert` | `Cmd+C` | `Ctrl+C` |
| 貼り付け | `Ctrl+Shift+V`、`Shift+Insert` | `Cmd+V` | `Ctrl+V` |

何も選択していないときのコピーのキーはプログラムに渡るので、`Ctrl+C` はこれまでどおりプログラムを中断します。Windows の `Ctrl+C` は、選択範囲をコピーしたあと選択を解除するので、もう一度押すと中断になります。プログラム自身が `Ctrl+C` と `Ctrl+V` を使う場合（vim の矩形選択、Emacs など）は、`config.py` で `TERMINAL_CTRL_CLIPBOARD = False` にしてください。2 つのキーはプログラムに渡り、ほかのキーでのコピーと貼り付けはそのまま使えます。

右クリックすると、選択範囲をコピーして選択を解除します。何も選択していなければ貼り付けます。Windows Terminal と同じ動きです。マウスを使うプログラムでは右クリックはそのプログラムに渡ります。コピーや貼り付けをするには `Shift` を押しながら右クリックしてください。

貼り付けた改行は `Enter` として送られるので、複数行を貼り付けると 1 行ずつ実行されます。

### シェルの環境

XeFM が起動したシェルには、ペインのディレクトリと選択項目を表す `XEFM_*` 変数、`XEFM_ACTIVE`、`[XeFM]` プロンプトマーカーが設定されます（[ユーザーガイド：サブシェル](XEFM_USER_GUIDE.ja.md#サブシェル)を参照）。これらの変数が表すのは、シェルが起動した時点のペインです。しばらく使い続けるセッションでは、代わりに [`xefmctl`](XEFMCTL_FEATURE.ja.md) で問い合わせてください。

zsh と bash 4.4 以降（macOS 標準の bash は 3.2）を起動するとき、XeFM は数行のシェル統合を追加します。これで、シェルがプロンプトで待っているときと、コマンドが終わったときがわかります。自分の起動ファイルはこれまでどおり実行されます。

### 隠れているセッションからの知らせ

セッションが隠れている間、ステータスバーには対応が必要なことが表示されます。10 秒以上かかったコマンドが終了または失敗したとき、プログラムが失敗したとき、そしてプログラムが通知（OSC 9 または OSC 777）を送ったときです。Claude Code などのツールは通知を送れます。進捗を報告するプログラム（OSC 9;4）の進捗もそこと、そのセッションのタブに表示されます。クリックするとそのセッションに戻ります。

シェル統合は、セッションで実行中のコマンドラインも Screens に伝えます。シェル統合がなくても、macOS と Linux ではそこで動いているプログラムの名前が表示され、Windows ではプログラムが設定したタイトルが表示されます。

## ターミナルでは

ターミナルで動く XeFM は、自分の中にもう 1 つターミナルを描くことはしません。サブシェルやターミナル向けのプログラムには XeFM が動いているターミナルが渡され、それらが終了すると XeFM に戻ります。ターミナルセッションも切り替える画面もないので、**Screens** がメニューとコマンドパレットにあるのは、[XeFM が描く AI エージェントの会話](AI_AGENT_SESSIONS_FEATURE.ja.md#xefm-が描く会話)を設定している場合だけです。

2 つのモードの違いはこの 1 点です。デスクトップアプリはシェルをペインの裏で動かし続けられますが、ターミナルで動く XeFM にはできません。ターミナルで並行して作業するには、ターミナルのタブやウィンドウ、または tmux を使ってください。XeFM から別のターミナルウィンドウを開くには、`PROGRAMS` にそのエントリを追加します。設定ファイルのテンプレートに、Terminal.app、iTerm、Windows Terminal、tmux の例があります。

## シェルから XeFM に問い合わせる

XeFM が起動したシェル（サブシェル、ターミナルセッション、`PROGRAMS` のエントリ）では、[`xefmctl`](XEFMCTL_FEATURE.ja.md) コマンドで、その XeFM の実行した時点での状態を問い合わせ、そのファイルマネージャーを操作できます。

```sh
xefmctl state                                  # what XeFM shows now
cp $(xefmctl pane selected) /tmp               # names without spaces
xefmctl pane cd .                              # bring the active pane here
xefmctl view build.log                         # Switch Screen takes you back to compare
xefmctl screen show files
```

XeFM が開ける場所ならどこでも検索し、ペインに一覧を表示し、XeFM を通してコピーし、あなたに質問することもできます。すべてのコマンドは [xefmctl](XEFMCTL_FEATURE.ja.md) を参照してください。XeFM が開く [AI エージェント](AI_AGENT_SESSIONS_FEATURE.ja.md)は、これを使ってあなたの隣で作業します。

## `TERMINAL` 設定項目

以前のバージョンは、デスクトップアプリで使うターミナルアプリを選ぶために `config.py` の `TERMINAL` を読んでいました。今はそれらを XeFM 自身のターミナルが動かすので、`TERMINAL` はもう使われません。まだ設定している config を読み込むと、XeFM が一度そう表示します。XeFM から自分のターミナルアプリを開くには、`PROGRAMS` にそのエントリを追加してください。
