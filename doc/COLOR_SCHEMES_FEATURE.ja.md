# 配色

[English](COLOR_SCHEMES_FEATURE.md) \| 日本語

## 概要

XeFM にはさまざまな**テーマ**が付属しています。いろいろなターミナル環境で見栄えのよいパレットに加えて、GUI バックエンドではパレットに画面効果と動く背景を組み合わせた、表現力豊かな「スクリーン」テーマもいくつかあります。テーマは実行中に切り替えられ、XeFM は最後に選んだものを覚えています。

このページでは、テーマそのもの、テーマがペインの背後に描くアニメーション背景、そしてテーマが有効にできる動き（ダイアログ、テキスト効果、ペインのフォーカス表示）を説明します。それらをすべて抑える 1 つのスイッチ `REDUCED_MOTION` も扱います。

## 使えるテーマ

XeFM は **Dark+** で起動し、標準的なパレットを一通り備えています。

- **Dark+**（既定）— 暗い背景に明るい色の文字。ディレクトリは黄色、シンボリックリンクはシアン。暗い場所でも目に優しい配色です。
- **Light+** — 白い背景に黒い文字。コントラストが高く、すっきりとした実用的な配色です。明るい背景のターミナルに向いています。
- **Monokai**、**Dracula**、**Nord**、**Solarized**（ライトとダーク）、**Gruvbox Dark** — エディターで人気のパレットです。

### 画面効果付きのレトロなテーマ

標準のパレットのほかに、XeFM には 4 つの**スクリーン**テーマが付属しています。それぞれパレットとおすすめの*画面効果*を組み合わせたものです。

- **Sci-Fi** — 戦術 HUD 風。深いネイビーに柔らかなシアンがかった白の文字、涼しげなシアンの枠と暖かいアンバーの選択色で、強い発光のブルームのにじみとグロー、周辺減光がかかります。走査線やローリンググリッチはありません。
- **Cyber** — データウォール風。黒に近いネイビーに密なシアンのテレメトリー、見つけたいもの（カーソル、インクリメンタルサーチ）にはアンバー、リンクにはマゼンタを使い、奥行きのある [`hologram`](#背景アニメーション) パネルがこちらへ漂ってくる背景に重なります。純粋に発光だけで構成され、強いブルームのにじみとグローがあり、走査線もローリンググリッチもないので、走査されるブラウン管ではなく投影されたホログラムのように見えます。ファイル名は現れるときにデコードされるように表示されます。
- **Segment LCD** — ポジ型／反射型のデジタル表示。セージグリーンの地に黒に近い「セグメント」（2 色だけ）で、走査線もグローもない平坦な表示です。黒いセグメント（文字）に柔らかなドロップシャドウが付き、浮き出たような LCD の見た目になります。
- **Shinagawa** — 夜の湾岸風。深いマリンブルーに白い文字で、下に光る [`wave`](#背景アニメーション) の面がうねりながら流れていきます。枠は青から白への 1 つのグラデーションですが、内容はそうではありません。ディレクトリは暖かいオレンジ（インクリメンタルサーチもそれに合わせた色）で、テキストビューアーには多彩なシンタックスの色が付くので、動く水面を背にしてもファイル一覧をひと目で見分けられます。効果は文字に付く柔らかなドロップシャドウだけで、文字を背景から浮き上がらせます。文字はすぐに表示され、動くのは水面だけです。

どれも **View → Theme** から選べます。

画面効果はフレーム全体に合成され、**デスクトップアプリ**（macOS／Windows）でのみ描画されます。ターミナルではパレットだけが表示されます。効果はそのテーマに切り替えると有効になり、別のテーマに切り替えると無効になります。`~/.xefm/config.py` の `THEMES` 辞書で、自作のテーマ（効果あり・なしのどちらも）を追加できます。[設定](CONFIGURATION_FEATURE.ja.md)を参照してください。

### 絵のテーマ

3 つのテーマは、ペインの背後に模様ではなく*絵*を置きます。写真のように照明して撮った場面がゆっくり動き、上のファイル一覧が読めるように暗めにしてあります。画面効果と同じく、絵が描かれるのはデスクトップアプリだけで、ターミナルではパレットだけが表示されます。

- **Earth** — ペインの背後に、軌道から見た地球。本物の地表と雲、光る大気、地球の縁から昇る太陽、星空があり、ゆっくり漂うカメラが、切り替わるレンズの見た目を通して地球を写します。数百のシーンのあいだを、ランダムにゆっくりと移っていきます。パレットは深い宇宙のネイビーで、枠には光る地平線の淡い青、カーソルとインクリメンタルサーチには日の出のアンバーを使います。構図やレンズの見た目の選び方は [Earth の場面](#earth-の場面)を参照してください。
- **Blocks** — 青い霧の中に並ぶ青黒い金属の柱を遠近で見た場面。柱はそれぞれ不揃いな速さで上下し、ときどき柱のあいだから光が漏れ出て、側面を照らしてから消えていきます。カメラは引きの構図、低い視点、真上近く、接写のあいだをゆっくり巡ります。光漏れはアクセントのシアン、カーソルはアンバーです。[Blocks の場面](#blocks-の場面)を参照してください。
- **Crystal** — XeFM 自身のテーマ。黒い玄武岩から生えたシアンの結晶（XeFM の名前の由来である*ゼノリス*）をスタジオの静物のように照明したマクロ撮影で、カメラは岩から数センチ離れて漂い、ピントは画面の中央にあるものを追います。グラファイトに、アイコンのシアンとアンバーを合わせています。[Crystal の場面](#crystal-の場面)を参照してください。

## 色が付くもの

どのテーマでも次のものが変わります。
- **ファイルの種類**：ディレクトリ、シンボリックリンク、通常のファイルで色が異なり、隠しエントリは背景に溶け込むように薄く表示されます（下記参照）
- **選択項目**：選択したファイルのハイライト
- **画面**：ヘッダー、フッター、ステータスバー、ペインの枠
- **ログメッセージ**：メッセージの種類ごとに異なる色
- **テキストビューアー**：コードファイルを表示するときのシンタックスハイライト
- **検索結果**：検索に一致した部分のハイライト

### 隠しファイル

隠しファイルを表示しているとき（`toggle_hidden`、**View → Show Hidden Files**）、隠しエントリはその種類の色を背景色の方向に薄めて描かれます。そのため、フォルダーやリンクであることは読み取れたまま、ペインのほかの項目とははっきり区別されます。Windows ではこれが唯一の手がかりです。Windows での隠しは名前の先頭のドットではなくファイル属性なので、これがなければ `desktop.ini` と普通のファイルは同じように見えます。

どのくらい薄めるかを変えたり、代わりに 1 つの単色にしたりするには、`~/.xefm/config.py` でテーマの `file_types` に `hidden` を指定します。

```python
THEMES = {
    'Ocean': {
        'file_types': {
            'hidden': 0.6,             # fade harder (0 = not at all)
            # 'hidden': (110, 110, 110),  # ...or one flat gray for every hidden entry
        },
    },
}
```

数値はある程度まではそのとおりになります。XeFM は隠しエントリの名前について、背後のペインに対する最低限のコントラストを保つので、大きな数値や背景に近い単色を指定しても、薄くなるのはその下限までです。隠しエントリは、読み飛ばせるほど控えめでありながら、見ようとすれば読めるだけのはっきりさが残ります。

## 使い方

### テーマを切り替える

XeFM の実行中に **View → Theme** から直接テーマを選びます。変更はすぐに反映されます。

### 既定のテーマ

XeFM は **Dark+** テーマで起動し、最後に切り替えたテーマを再起動後も覚えています。既定の配色を指定する設定項目はありません。テーマを追加したりカスタマイズしたりするには、`~/.xefm/config.py` の `THEMES` 辞書を使います（[設定](CONFIGURATION_FEATURE.ja.md)を参照してください）。

### テーマのキーを割り当てる

テーマの順送りには、既定ではキーが割り当てられていません。キーボードで順送りするには、`~/.xefm/config.py` で `toggle_color_scheme` を割り当てます。

```python
KEY_BINDINGS = {
    'toggle_color_scheme': ['Y'],  # Pick any free key
    # ... other bindings
}
```

## ターミナルとの互換性

XeFM はターミナルが何に対応しているかを自動で検出します。

- **最近のターミナル**：24 ビットカラー（数百万色）をすべて使えます
- **古いターミナル**：基本の 8 色または 16 色になります（それでも見栄えは十分です）
- **すべてのターミナル**：テーマはどこでも使えます（画面効果とアニメーション背景は GUI バックエンド専用で、ターミナルではパレットだけが表示されます）

## 背景アニメーション

テーマは、ファイルのペインの*背後*に、ゆっくり動くアニメーションの場面を描けます。アニメーションは UI 全体の下に描画され、画面が完全に不透明でないところから透けて見えるので、ファイルの上に乗った飾りではなく、生きた壁紙のように見えます。

アニメーションは**テーマ自身の色**で描かれます。線の色はテーマの前景色から、背景はテーマの背景色から取られるので、どのテーマ（や自作のパレット）を使っても、場面はパレットに合った色になります。`blocks` ではこの色が柱のあいだから漏れる光に、`crystal` ではガラスの色になります。例外は `earth` で、地球を自然な色で描いた絵なので、テーマから取るのは表示の下地になる背景色だけです。

> **デスクトップモードのみです。** アニメーションには本物のピクセルが必要です。描画するのは macOS／Windows のデスクトップバックエンドです。ターミナルにはセルより細かいピクセルがないので、この設定は何も言わずに無視され、テーマの単色の背景になります。

### 使えるアニメーション

| 名前 | 見た目 |
|------|--------------------|
| `starfield` | 消失点からこちらへ流れてくる星。近づくにつれて長く明るくなる動きの軌跡として描かれます。 |
| `rain` | 尾が薄れていく落下する筋。列ごとに速さが異なる、古典的な蛍光体ターミナルの雨です。 |
| `constellation` | ゆっくり漂う点が近くの点と線で結ばれ、点が通り過ぎるにつれて線が現れたり消えたりします。 |
| `grid` | ワイヤーフレームの通路を飛んでいく場面。床、天井、両側の壁がグリッドになっていて、消失点に向かって集まります。カメラがゆっくり漂いながら向きを変えるので、消失点もさまよいます。 |
| `wave` | うねる波の面の上を流れる密な粒子の場。色のグラデーションが面に沿って移ろいます。 |
| `datastream` | 横方向のテレメトリーの流れ。何層にも重なったダッシュの列がそれぞれ異なる速さで流れていきます。ほとんどは短く、ときどき長い筋が混じり、どれも先頭が明るく、一部は小さな縦の刻みで終わります。にぎやかな領域と静かな領域が場の中を漂います。 |
| `earth` | 軌道から見た地球。地表、カメラが動くと地面に対してずれて見える 3 つの高さの雲、縁に朝焼けと夕焼けが出る光る大気、海に反射する日の光、街の灯りのない暗い夜の側、星と淡い天の川があります。ゆっくりしたカメラが構図のあいだを移り、レンズの見た目（フィルム、アナモルフィック、ブラウン管など）を選べます。レンズは絵だけにかかり、ペインには決してかかりません。[Earth の場面](#earth-の場面)を参照してください。 |
| `blocks` | 青い霧の中の角の丸い金属の柱がゆっくり不揃いに上下し、ときどき隙間から光が漏れて側面を照らします。カメラは約 5 分かけて構図のあいだを巡ります。[Blocks の場面](#blocks-の場面)を参照してください。 |
| `crystal` | ごつごつした黒い玄武岩から生えた小さなシアンの結晶のマクロ。光を屈折させる緑の内包物入りのガラス、ガラスと岩の境目の苔のような被膜、ゆっくり動くスタジオのキーライトとシアンのリムライト、シアンに色づく影があり、画面中央のものにピントが合います。[Crystal の場面](#crystal-の場面)を参照してください。 |
| `hologram` | 奥行きのあるホログラムのパネルがこちらへ漂ってくる場面。それぞれが小さな平らな表示で、左から右へ自分で打ち出されていく疑似テキスト、棒グラフと折れ線グラフ、進捗バー、リングゲージ、ワイヤーフレームのメッシュなどがあり、ところどころに暖かいアクセント色が入ります。場がゆっくり通り過ぎるなか、パネルはそれぞれ自分のタイミングで浮かび上がり、留まり、消えていきます。背後には遠くのパネルの細かなもやがあり、消失点から外側へ数本の太い速度の筋が走り、ぼけた点や線が全体の上をゆっくり漂い、明るい流れ（バーコードのような断片、ダッシュ、点）が横のレーンを高速で走ります。 |

UI ツールキット自身の `cube`（回転するワイヤーフレーム）も使えます。これは完成した見た目というより、描画処理の参照用の場面として用意されているものです。

### どこで動くか

どの場面も **GPU シェーダー**で、グラフィックカード上でピクセルごとに計算されます。そのおかげで、密度が高く、単色の線ではなく本物の色のグラデーションを使え、XeFM が何もしていない間はほとんど負荷がかかりません。XeFM が画面を再描画しなくても、グラフィックカードが UI の背後で場面を進めてくれます。

アニメーションには macOS または Windows の**デスクトップモード**が必要です。ターミナルには描画するピクセルがないので、`animation` キーは無視され、テーマの単色の背景になります。使える GPU シェーダーのない、まれなデスクトップ環境でも同じです。`earth`、`blocks`、`crystal` は厳密な意味でのデスクトップモードが必要で、ブラウザー（Web）モードでは単色の背景になります。

### 有効にする

アニメーションはテーマごとに選びます。内蔵のテーマでは、**Sci-Fi** に starfield、**Cyber** に hologram、**Shinagawa** に wave、**Earth** に earth、**Blocks** に blocks、**Crystal** に crystal が付いています。**View → Theme** から選んでください。

自作のテーマで使うには、`~/.xefm/config.py` の `THEMES` 辞書のテーマに `animation` キーを追加します。

```python
THEMES = {
    'Deep Space': {
        'base': 'Dark+',
        'animation': 'starfield',
        'opacity': 0.6,          # let the scene show through the panes
    },
}
```

#### `opacity` — アニメーションを透けて見せる

アニメーションは UI の*背後*に描かれるので、画面が完全に不透明だと、レイアウトの隙間からしか見えません。テーマの `opacity` の値（0〜1）は、ペインと行の背景がどれだけ不透明かを決めます。値を下げると、場面がそれらを透けて見えるようになります。

- `1.0` — UI は完全に不透明（既定）。アニメーションは実質的に見えません。
- `0.6` — 最初に試すのによい値です。場面がはっきり見え、文字もくっきりしたままです。
- `0.3` — とても透明です。雰囲気は出ますが、使っているパレットで読みやすさを確認してください。

文字、枠線、ダイアログのボックスは常に不透明なので、`opacity` を下げても画面が読めなくなることはありません。

#### 使っていないときは消えていく

ずっと動き続けるアニメーションは、ほかのものを読んでいる間もマシンを働かせ続け、バッテリーを減らしてしまいます。そうならないように、次のように動きます。

- 入力が 15 秒ほどないか、XeFM がフォーカスを失うとすぐに、アニメーションは**ごくゆっくりとフェードアウト**し、消えるまでさらに 40 秒ほどかかります。フェードは気づかないほど穏やかにしてあります。急に途切れると、動きそのものと同じくらい目を引いてしまうからです。
- フェードしている間も、動きはずっと普段の速さのままです。遅くはなりません。場面が目に見えて減速し*かつ*フェードしていくと、2 つのことが同時におかしくなっているように見えますし、フェードの目的は止まるところを見せないことだからです。
- 最後に残るのはテーマの単色の背景です。XeFM に付属する場面のほとんどは純粋な動き（降る雨、流れる星、飛んでいく通路）で、そうした場面には止めるに値するフレームがありません。止めてしまうと、雨粒や星がたまたまあった場所に取り残され、落ち着いたというより XeFM が固まったように見えます。溶けるように消えれば、パレットにもともとあるものが残ります。
- `earth`、`blocks`、`crystal` は例外です。どのフレームも絵なので、フェードする代わりにゆっくり減速して止まり、その絵のまま**留まります**。
- さらに `earth` は、XeFM に戻ってきたときにそのシーンの続きではなく、ランダムに選んだ新しいシーンへ数秒かけて移ります。切り替わるのは戻るたびに 1 回だけです。ほかのアプリが前面にあるときに XeFM の上でマウスを動かしても、戻ってきたことにはなりません。
- キーを押すかマウスを動かした瞬間に、**ゆっくりと戻ってきます**。
- 止まったところからそのまま再開します。XeFM を 1 時間放っておいても、wave は「本来なら」あったはずの位置に飛ぶのではなく、離れたところから続きます。

システムの**視差効果を減らす**設定がオンの場合、場面は止まりますが、消えずに*残ります*。フェード自体が動きになりますし、あなたはまだマシンの前にいるからです。

設定することは何もなく、作業が中断されることもありません。止まっている間、XeFM の消費電力は単色の背景のときと変わりません。

#### 速さと強さを調整する

調整するには、`animation` に名前ではなく辞書を指定します。

```python
'animation': {'type': 'rain', 'speed': 1.0, 'opacity': 0.8},
```

| キー | 意味 |
|-----|---------|
| `type` | どのアニメーションか（上の表を参照）。 |
| `speed` | 動きの速さの倍率。`1.0` が調整済みの見た目で、XeFM の既定は `0.6` です。`0` で場面が止まります。 |
| `opacity` | 場面そのものをどのくらい濃く描くか（0〜1）。テーマ全体の `opacity` と混同しないでください。そちらは場面の上にある UI についての値です。 |
| `color` | テーマの前景色以外にしたい場合の、場面の基調色。場面はこの色をそのまま塗るのではなく、自分の色付けの基準にするので、グラデーションのある場面はグラデーションを失わず、この色に合わせて色合いが変わります。 |

どのアニメーションも、あえてゆっくり控えめにしてあります。実際に作業しているファイルマネージャーの背後にあるものなので、ファイル名と注意を奪い合うのではなく、背景に留まるように調整されています。`speed` を `1.0` よりかなり大きくしても動きますが、実際に使っていると気が散りやすくなるでしょう。

#### Earth の場面

何も指定しなければ、`earth` は構図（10 種類、それぞれ 12 通りの構成。地球の周りの位置、高度、傾きを変え、画面を回転させて地球が下にも横にも上にも来るようにしたもの）とレンズの見た目（10 種類）を組み合わせて**シーン**を作ります。組み合わせは 1,200 通りです。各シーンは `speed` が `1.0` のとき約 50 秒（約 30 秒とどまり、次のシーンへ約 18 秒かけてゆっくり移る）で、その間ずっとカメラがゆっくり一定の速さで動きます（地球の周りを回り、近づいたり離れたりし、地球が画面を横切りながら回り、太陽もそれに合わせてゆっくり動きます）。そのあと、ランダムに選んだ次のシーンへ 1 つのなめらかな動きで移ります。シーンの中の動きとシーン間の移動は途切れずにつながります。XeFM は起動時にランダムなシーンから始まり、アイドルから戻ると新しいシーンに切り替わります。

絵はわざと暗めにしてあります。どのピクセルも白の半分より明るくならない（`brightness`）ので、日の当たる海の上でもファイル名が読めます。

同じ辞書で独自のキーを 5 つ受け付けます。

```python
'animation': {'type': 'earth', 'shot': 'rise', 'lens': 'film',
              'clouds': 3.0, 'exposure': 0.85},
```

| キー | 意味 |
|-----|---------|
| `shot` | 1 つの構図（下の表）に留めます。省略するか `'auto'` にすると、シーンごとにランダムに選びます。 |
| `lens` | カメラの見た目（下の表）。省略するか `'auto'` にすると、シーンごとにランダムに選びます。1 つを指定するとそれに固定し、リストを指定するとその中から選びます：`['clean', 'film', 'anamorphic']`。辞書で見た目を調整できます：`{'preset': 'film', 'grain': 0}`。 |
| `clouds` | 雲を地面からどれだけ持ち上げるか（0〜8）。`1` が実際の高さで、既定の `3` では軌道からでも雲が地表に対してずれて見えます。 |
| `exposure` | カメラが取り込む光の量（0.1〜4）。既定は `1`。 |
| `brightness` | 絵の最大の明るさ。白に対する割合（0〜1）。既定は `0.5`。 |

構図：

| `shot` | 見えるもの |
|--------|--------------|
| `day` | 昼の全景。アフリカとヨーロッパ。 |
| `dawn` | 西太平洋の上、地球の丸みに沿った日の出。 |
| `crescent` | 背後から照らされた細い三日月。縁で大気が光ります。 |
| `leo` | 高度約 250 km の低軌道から、ヒマラヤ越しに地平線を見渡します。 |
| `terminator` | アンデスを横切る昼と夜の境界。 |
| `glint` | 太平洋中央に映る太陽。 |
| `rise` | 太陽が地球の縁の向こうへ沈み、また現れます。沈むにつれて小さく赤くなり、隣の大気が明るく広がります。 |
| `polar` | 北極の上空。 |
| `horizon` | 低軌道から見る、地平線に沿った日の出。 |
| `ocean` | 低軌道から斜めに見下ろす、昼の太平洋。 |

固定した構図もゆっくり動き、構成はこの表のとおりです。各構図のほかの 11 通りの構成は、`shot` を指定しないときだけ現れます。

レンズ。かかるのは絵だけで、ペイン、文字、ダイアログが歪んだり、ぼけたり、粒子が乗ったりすることはありません。

| `lens` | 見た目 |
|--------|------|
| `clean` | 最も明るい光のまわりの軽いにじみと、柔らかな周辺減光。 |
| `aberration` | 端に向かう色ずれと、わずかな樽型の歪み。 |
| `mono` | 粒子のある白黒。 |
| `film` | 暖かいハイライト、涼しげな影、光のまわりの赤いにじみ、粒子。 |
| `anamorphic` | シネマスコープの帯、太陽を横切る青い横の光条、かすかなフレア。 |
| `flare` | 画面の中心を挟んで反対側に映るレンズフレアのゴースト。 |
| `fisheye` | 強い魚眼。 |
| `crt` | 曲面のブラウン管と走査線。 |
| `infrared` | 赤外フィルムが草木や空を写すような偽色。 |
| `night-vision` | 緑色の暗視スコープ。 |

テクスチャは NASA の Blue Marble の画像で、クレジットは `xefm/assets/earth/SOURCES.md` にあります。ノートパソコンでは、動いている間はほかのアニメーションよりかなり多くの GPU 時間を使います。ほかと同じく、XeFM が何もしていないときは止まり、負荷はかかりません。

#### Blocks の場面

`blocks` は独自のキーを受け付けます。

```python
'animation': {'type': 'blocks', 'leaks': 1.5, 'motion': 0.6, 'camera': 0.5},
```

| キー | 意味 |
|-----|---------|
| `leaks` | 柱のあいだから光が漏れる頻度（0〜3）。`1` が調整済みの値で、`0` で漏れなくなります。 |
| `leak_strength` | 漏れる光の明るさ（0〜3）。既定は `1`。 |
| `motion` | 柱が上下する大きさ（0〜2）。`0` で止まります。既定は `1`。 |
| `camera` | カメラが巡る速さ（0〜3）。`0` で 1 つの視点に留まります。既定は `1`。 |
| `exposure` | カメラが取り込む光の量（0.1〜4）。 |
| `brightness` | 絵の最大の明るさ。白に対する割合（0〜1）。既定は `0.5`。 |

漏れる光はテーマの色（`color`、なければ前景色）、霧はテーマの背景色です。この場面は `speed` が `1.0` のときに合わせて調整してあり、**Blocks** テーマはその値を使います。

#### Crystal の場面

`crystal` は独自のキーを受け付けます。

```python
'animation': {'type': 'crystal', 'focus': 0.5, 'brightness': 0.6},
```

| キー | 意味 |
|-----|---------|
| `focus` | 被写界深度の強さ（0〜2）。`1` が調整済みの値で、`0` ですべてにピントが合います。 |
| `exposure` | カメラが取り込む光の量（0.1〜4）。 |
| `brightness` | 絵の最大の明るさ。白に対する割合（0〜1）。既定は `0.5`。 |

ガラスはテーマの色（`color`、なければ前景色）を使います。ガラスの色合い、内側の光、影の色、リムライトがこの色に従い、アイコンのシアンで設計どおりの見た目になります。XeFM でいちばん負荷の高い場面なので、毎秒 30 フレームで描画します。カメラの動きがゆっくりなので違いはわかりません。テーマを選ぶと最初の 0.5 秒ほどで岩を準備し、その間は単色の背景が表示されます。この場面は `speed` が `1.0` のときに合わせて調整してあり、**Crystal** テーマはその値を使います。

### 代わりに画像を使う

背景はアニメーションではなく静止画像にもできます。テーマのドキュメントの `wallpaper` キーを参照してください。テーマの背景は 1 つだけです。`wallpaper` と `animation` の両方を指定すると、壁紙が使われます。

## 動きとテキスト効果

GUI バックエンドでは、XeFM はいくつかのものをアニメーションさせます（現れるダイアログ、UI の背後を漂う Sci-Fi テーマの星空など）。また、どちらのファイルペインにフォーカスがあるかを示します。この節では、何が見えるか、それをどう変えるかを説明します。

### ダイアログ

すべてのモーダル（入力欄、フィルターやお気に入りの選択画面、一括リネーム、テキスト／差分／ディレクトリ差分のビューアー）は同じように現れます。フェードインしながら 92% から実寸まで大きくなり、急に減速してすべるように止まります。

選択画面は 180 ms、全画面のビューアーは 140 ms です。ビューアーはたいてい意図して開くものなので、短くしておくことで、キー操作から遅れているように感じさせないようにしています。

ターミナルには合成機能がないので、同じ意図が 2 フレームで表現されます。内側に縮めたフレームを 1 つ表示し、次に完成したボックスを表示します。失われるものはなく、刻みが粗くなるだけです。

### 現れる文字（Sci-Fi）

**Sci-Fi** テーマでは、文字は現れるときに自分で打ち込まれるように表示されます。ディレクトリに入るとファイルペインが左から右へ埋まっていき、ダイアログが開くときにはそのラベルも同じように表示され、**ログペインの新しい各行**も書き込まれるときに同じように表示されます。ほかのテーマでは文字は普通に描かれます。

この効果は何かが*現れた*とき、つまり新しい一覧、ダイアログ、新しいログの行のときに働きます。スクロール中や、ステータスの値が切り替わったときにはあえて**働きません**。読んでいるものとの間に割り込まないようにするためです。すでに読んだログの行までスクロールして戻っても、その行には何も起きません。

#### 別の効果を選ぶ

5 つのスタイルが付属しています。どのテーマでも、`config.py` でどれかを指定できます。

```python
THEMES = {
    'Dracula': {
        'text_effect': 'scatter',   # or 'typewriter', 'decode', 'wipe', 'flicker'
        # ...or tune it:
        # 'text_effect': {'kind': 'typewriter', 'duration_ms': 300,
        #                 'stagger_ms': 8, 'max_rows': 120},
    },
}
```

- `typewriter` — 文字が左から右へ現れ、まだ現れていない部分には何も表示しません（Sci-Fi の既定）
- `scatter` — 文字が**ランダムな順番**で、それぞれ最終的な位置に直接現れます。横にずれることはありません。打ち込まれるというより、メッセージが実体化していくように見えます
- `decode` — まだ現れていない部分は、表示が通り過ぎるまででたらめな文字としてかき回されます
- `wipe` — まだ現れていない部分は、確定するまでブロック文字で埋められます
- `flicker` — 文字は表示されていますが、乱れたあとで落ち着きます

`duration_ms` は 1 つの文字列にかかる時間、`stagger_ms` は**行**ごとに加わる遅れで、これによって一覧がペインの上から下へ流れるように表示されます。`max_rows` はアニメーションする行数の上限で、それ以降の行はそのまま表示されるので、とても縦長のウィンドウでも何秒も流れ続けることはありません。名前を間違えると、何かが壊れるのではなく効果がオフになります。

#### オプション

`typewriter`、`scatter`、`decode` では 2 つの調整ができます。

```python
'text_effect': {
    'kind': 'typewriter',
    'flash': 0.08,        # each character flashes as a solid block as it lands
    'hidden': 'scramble', # not-yet-revealed characters churn instead of staying blank
},
```

- **`flash`** — 文字が確定する瞬間に、一瞬だけ塗りつぶしたブロックとして表示され、それから本来の文字に落ち着きます。`typewriter` では入力カーソルのように、`scatter` では文字が打ち付けられるように見えます。値は全体の時間に対する割合なので、およそ `1 / len(text)` にすると 1 文字分ほどの時間だけ光ります。たいていの文字列には `0.06`〜`0.12` が合います。
- **`hidden`** — まだ現れていない文字に何を表示するか。既定では空白です。`'scramble'` にするとでたらめな文字がかき回されます（`decode` があのように見えるのはこのためで、`scatter` に適用するとより騒がしく実体化します）。

**編集中**の文字は決してアニメーションしません。テーマが何を指定していても、入力欄は常に実際の値を表示します。

#### すべてが同じ効果を使うわけではない

**テキストビューアー**は、テーマがどのスタイルを指定していても、`flash` 付きの `scatter` を使います。全画面の文字には目で追うべき 1 つの場所がないので、左から右への表示はゆっくりしたワイプに見えてしまいますが、あらゆる場所に一斉に現れれば、同じ時間でページが埋まるからです。

それでも、肝心な点ではテーマに従います。テーマにテキスト効果がなければ、ビューアーもほかと同じように普通に開きますし、タイミングは独自に決めずテーマから取ります。

### カーソル行

カーソルのある行は、テーマのカーソル色で示されます。デスクトップアプリでは行を囲む枠線、ターミナルでは**行全体の下に引かれる線**で、幅の広い一覧でもこれで見つけられます。

その色が付くのは、**作業中**のペインだけです。反対側のペインはカーソルを無彩色のグレーで示します。そのため 2 つが同じに見えることはなく、色をひと目見れば Enter がどちら側に働くかがわかります（以前は、待機中の表示は同じ色を暗くしたものでしたが、線の幅ではそれが同じ表示に見えてしまいました）。

**XeFM は、ターミナルが実際に表示できる印を自分で選びます。** 最近のターミナルのほとんど（Windows Terminal、iTerm2、WezTerm、kitty、GNOME Terminal、Ghostty、Alacritty、Konsole など）は下線を独自の色で描けるので、そこでは線が表示されます。macOS 標準の Terminal.app など、それができないターミナルでは、線が行の文字色で出てしまい、「この行に下線がある」ことしか伝わらず、どちらのペインにいるかはわかりません。そのため、カーソル行は代わりにカーソル色の `[` … `]` で示されます。どちらの表し方も同じことを伝え、どちらも設定は不要で、どちらも一覧の両端を同じく 1 列ずつ使います。そのため、どのターミナルでも、カーソル行の示し方以外はペインの見た目が同じになります。

### ペインのフォーカス

作業中のペインは 2 つの手がかりで示されます。どちらもテーマごとの設定で、既定でオンにしているのは Sci-Fi テーマだけです。

- **コーナーブラケット**がフォーカスのあるペインを囲みます（GUI のみ。下記参照）。
- **待機中のペインの文字**が、ペインの背景色の方向へ少し沈みます。

待機中のペインのファイル名は読めるままです。この色の薄めは XeFM の読みやすさの処理の前に適用され、その処理がコントラストの下限より下に押し下げられた色を下限の上まで引き上げます。テーマの設定で待機中のペインを読めなくすることはできません。

ターミナルではブラケットは省かれます。文字のグリッドにはセルより細かい余地がなく、飾りのために列や行を丸ごと確保すると一覧の表示領域が実際に減ってしまうからです。そのためターミナルでのフォーカスは、フォーカスのあるペインでは色付き、待機中のペインではグレーになるカーソル表示で示されます。色の変更は場所を取らないので、文字を薄める処理はターミナルでも適用されます。

#### ほかのテーマで有効にする

どちらも `config.py` に書く普通のテーマのデータです。

```python
THEMES = {
    'Dracula': {
        # Brackets in the theme accent, default arm length:
        'pane_frame': True,
        # ...or spell it out:
        # 'pane_frame': {'color': (130, 205, 255), 'arm': 2, 'thickness': 1.0},

        # Default wash strength:
        'pane_dim': True,
        # ...or set your own, 0.0 (untouched) to 1.0 (invisible):
        # 'pane_dim': 0.15,
    },
}
```

## 動きを減らす

装飾的な動き（ダイアログの拡大表示、テキスト効果、上で説明したテーマのアニメーション背景）をすべて抑えるには、`config.py` で次のように設定します。

```python
REDUCED_MOTION = True
```

オンにすると次のようになります。

- ダイアログは拡大しながらではなく、すぐに表示されます。
- 文字はデコードされるようにではなく、すぐに表示されます。
- テーマのアニメーション背景（Sci-Fi の星空、Shinagawa の波、Earth の地球、Blocks の柱、Crystal のマクロなど）は減速して止まり、静止したフレームのままになります。
- CRT 風のテーマはグロー、走査線、周辺減光を保ちます（画面は CRT のように見えたままです）が、流れる帯とちらつきは止まります。

すべてが途中で止まるのではなく**最終的な**状態になるので、オンにしても何かが隠れることはありません。

知っておきたいこと：これが影響するのは装飾だけです。進捗バー、ファイル一覧の再読み込み、検索結果など、機能的な更新はすべてこれまでどおり動きます。

アニメーションの各フレームが画面全体の再描画になる、遅い SSH 接続でも設定しておく価値があります。

## トラブルシューティング

### テーマを切り替えても色が変わらない
- ターミナルが色に対応していることを確認してください
- 設定で色が有効になっていることを確認してください
- XeFM を再起動してみてください

### 色がおかしく見える
- ターミナルがフル RGB カラーに対応していないのかもしれません（これは普通のことです）
- XeFM は、そのターミナルで使える、より単純な色を自動で使います
- もっと多くの色を使いたい場合は、別のターミナルを試してください

### 色が明るすぎる／暗すぎる
- 別のテーマに切り替えてください（**View → Theme**）
- ダークテーマ（Dark+）は暗い背景のターミナルに向いています
- ライトテーマ（Light+）は明るい背景のターミナルに向いています

## ヒント

- **暗いターミナル**：Dark+（既定）などのダークテーマを使ってください
- **明るいターミナル**：Light+ などのライトテーマに切り替えてください
- **SSH 接続**：SSH 越しでも色は使えます
- **Screen／tmux**：ターミナルマルチプレクサーでも色は使えます
- **いろいろなターミナル**：いくつかのテーマを試して、どれがいちばんよく見えるか確かめてください

## さらに詳しく知るには

- **XeFM の中で**：`F1` を押すとヘルプが開き、すべてのキーバインドが一覧表示されます
- **ログメッセージ**：XeFM は、ターミナルがどの種類の色に対応しているかを表示します

テーマ機能によって、XeFM はどんなターミナル環境でも見栄えよく表示されます。
