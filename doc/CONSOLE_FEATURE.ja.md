# コンソール

[English](CONSOLE_FEATURE.md) \| 日本語

コンソールは、ペインで作業している間も動き続けるシェルです。**Tools → Console**（`toggle_terminal`）で開きます。初回はアクティブなペインのディレクトリでシェルが起動します。同じキーでまた隠れ、あとで開くと、入力中のコマンド、出力、実行中のビルドなど、すべてがそのまま残っています。

サブシェル（`subshell`）はこれとは違い、1 回限りです。XeFM はサブシェルの終了を待ち、シェルを終了するとペインに戻ります。このディレクトリで手早くコマンドを実行するときはサブシェルを、ほかのことをしている間も続く作業にはコンソールを使ってください。

## デスクトップアプリでは

コンソールは XeFM のウィンドウの中に、ペインの代わりに、XeFM 自身のターミナルで描画されます（このターミナルが動く環境については[外部ターミナル](EXTERNAL_TERMINAL_FEATURE.ja.md#ターミナルを選ぶ)を参照してください）。

- **隠す**には同じキーを押します。中のプログラムが終了したあとは `Esc` でも隠れます。隠れたときに、ペインはディレクトリを読み直します。
- シェルで **`exit`** するとセッションが終わり、ペインに戻ります。失敗したプログラムは最後の画面を残します。`Enter` でもう一度起動し、`Esc` で隠します。
- シェルが動いている間に `terminal.close` で**閉じる**ことができます。そこで動いているものが止まるので、XeFM は先に確認します。
- **複数のセッション。** **Tools → Terminal Sessions…**（`terminal_sessions`、コンソールの中からは `terminal.sessions`）で、各セッションとその状態が一覧になります。`Enter` で選んだセッションに切り替わり、最後の行はアクティブなペインのディレクトリで別のシェルを起動し、削除キー（`remove_list_item`）はハイライト中のセッションを終わらせます。コンソールのキーは、最後に使ったセッションに戻ります。
- セッションが動いている間に **XeFM を終了**すると、先に確認してから、そのセッションを止めます。

コンソールのシェルには `XEFM_ACTIVE` と `[XeFM]` プロンプトマーカーが設定されますが、サブシェルに設定される、ペインのディレクトリや選択項目を表す `XEFM_*` 変数は設定されません。ペインで何かを変えた途端に古くなってしまうからです。代わりに [`xefm` コマンド](#シェルから-xefm-に問い合わせる)で XeFM に問い合わせてください。

キーは[キーマッププリセット](KEYMAP_PRESETS_FEATURE.ja.md#すべてのキーの一覧)にあります。

### コンソールに入力する

**Tools → Type Selection into Console**（`insert_into_console`）は、選択項目（なければカーソル位置の項目）のフルパスを、そのシェル向けにクォートしてコンソールのプロンプトに入力し、コンソールを表示します。コマンドを仕上げて `Enter` を押してください。`cd_console_here` は、同じように `cd` とアクティブなペインのディレクトリを入力します。コンソールの中からは、`terminal.insert_selection` でアクティブなペインの選択項目を入力できます。どれも、`KEY_BINDINGS` で割り当てるまではキーがありません。

XeFM が入力するのは、シェルがプロンプトで待機しているときだけで、実行中のコマンドに入力することはありません。それがわかるのは zsh と bash 4.4 以降（macOS 標準の bash は 3.2）で、XeFM は自分のターミナルでこれらを起動するときに、数行のシェル統合を追加します。自分の起動ファイルはこれまでどおり実行されます。それ以外のシェルの場合、コマンドの実行中、そしてターミナルでは、テキストは代わりにクリップボードに送られ、ログにその理由が表示されます。

### 隠れているコンソールからの知らせ

コンソールが隠れている間、ステータスバーには対応が必要なことが表示されます。10 秒以上かかったコマンドが終了または失敗したとき、あるいは中のプログラムが通知（OSC 9 または OSC 777）を送ったときです。Claude Code などのツールは通知を送れます。進捗を報告するプログラム（OSC 9;4）の進捗もそこに表示されます。クリックするとコンソールに戻ります。

## シェルから XeFM に問い合わせる

XeFM が起動したシェル（コンソール、サブシェル、`PROGRAMS` のエントリ、`TERMINAL` で開いたシェル）では、`xefm` コマンドで、その XeFM の実行した時点での状態を問い合わせられます。

| コマンド | 動作 |
|---|---|
| `xefm selected` | 選択項目のフルパスを 1 行に 1 つずつ表示（`-0`：`xargs -0` 用に NUL で区切る） |
| `xefm focused` | カーソル位置の項目のフルパスを表示 |
| `xefm pwd` | ペインのディレクトリを表示 |
| `xefm cd [PATH]` | ペインを `PATH`（シェルのディレクトリからの相対パス）に移動。`PATH` を省略するとシェルのディレクトリに移動。ファイルを指定すると、そのフォルダーに移動してカーソルをそのファイルに置く |
| `xefm view FILE` | `FILE` を XeFM のビューアーで開く |
| `xefm sessions` | コンソールのセッションを一覧表示。`*` は自分のいるセッション |

`--pane this`（既定、アクティブなペイン）、`--pane other`、`--pane left`、`--pane right` でペインを選びます。例：

```sh
cp $(xefm selected) /tmp           # names without spaces
xefm selected -0 | xargs -0 du -sh
xefm cd .                          # bring the active pane to this shell's directory
xefm view build.log
```

`xefm ext check` など、ほかの `xefm` コマンドはそこでも通常どおり使えます。シェルを起動した XeFM が終了している場合は、コマンドがそう伝えます。ターミナルモードのサブシェルの実行中は XeFM がその終了を待っているため、そこで使えるのは読み取るだけのコマンド（`selected`、`focused`、`pwd`、`sessions`）だけです。

## ターミナルでは

ターミナルで動く XeFM は、自分の中にもう 1 つターミナルを描画しません。代わりに、コンソールはアクティブなペインのディレクトリで、独立したウィンドウとして開きます。

| XeFM が動いている場所 | コンソールの開き方 |
|---|---|
| tmux | 新しい tmux ウィンドウ |
| WezTerm | 新しいタブ（`wezterm cli spawn`） |
| kitty | 新しいタブ（`kitty.conf` で `allow_remote_control` が必要） |
| それ以外（このコンピューター上） | [外部ターミナル](EXTERNAL_TERMINAL_FEATURE.ja.md#ターミナルを選ぶ)と同じく、プラットフォームのターミナルのウィンドウ |
| それ以外（SSH 経由） | 開きません。`TERMINAL` を設定するか、XeFM を tmux の中で動かしてください |

`config.py` で `TERMINAL` を設定している場合は、そちらが使われます。こうして開いたウィンドウは XeFM ではなくターミナルアプリケーションのものです。コンソールのキーはそれを隠すのではなく別のウィンドウを開き、XeFM を終了しても動き続けます。
