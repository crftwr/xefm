# XeFM デスクトップモードガイド

[English](DESKTOP_MODE_GUIDE.md) \| 日本語

## 概要

XeFM は、Windows と macOS で GPU アクセラレーションを使うネイティブのデスクトップアプリケーションとして動作できます。ターミナルモードでおなじみの強力なキーボード中心のインターフェースはそのままに、モダンなウィンドウ環境で使えます。

## クイックスタート

### 使い始めるには

**デスクトップ版のパッケージをインストールしてください。** これが XeFM をデスクトップアプリとして動かす正式な方法です。ネイティブの `.app`（macOS）または自己完結した `XeFM.exe` のフォルダー（Windows）で、Python が同梱されているので、自分で Python をインストールする必要はありません。Windows では **[Microsoft Store](https://apps.microsoft.com/detail/9PK2X44W810V)** からインストールします。macOS の DMG（と Windows のポータブル zip）は **[GitHub の最新リリース](https://github.com/crftwr/xefm/releases/latest)** で公開されています。手順は[次のセクション](#デスクトップアプリのパッケージのインストール)で説明します。

あとはほかのアプリケーションと同じように起動します。macOS では Launchpad、Spotlight、Dock から、Windows ではスタートメニューやタスクバーにピン留めしたショートカットからです。

#### `xefm --backend gui` ではいけないのはなぜですか？

`--backend gui` フラグを使うと、同じウィンドウをターミナルから開けます。このフラグがあるのは、XeFM の*開発*にこの方法を使うためです。実際に XeFM を**使う**方法としては、次の 3 つの理由でおすすめできません。

- **macOS のアクセス権限がおかしくなります。** ターミナルから起動した GUI はそのターミナルの子プロセスなので、macOS はプライバシーに関する要求をすべてそのターミナルのものとして扱います。デスクトップ、書類、ダウンロード、iCloud Drive、リムーバブルボリュームへのアクセスは、XeFM ではなく *Terminal.app*／*iTerm* に許可（または拒否）されます。確認メッセージには別のアプリの名前が表示され、ファイル操作が XeFM の設定ではどうにもならない権限エラーで失敗することもあります。インストールした `.app` は独自のバンドル ID を持つので、自分のアクセス権限を要求し、保持します。
- **アプリケーションのアイコンが正しく表示されません。** これはどちらのプラットフォームでも起こります。アプリバンドル（macOS）や同梱のランチャー実行ファイル（Windows）がないと、Dock、タスクバー、Cmd／Alt-Tab の切り替え画面に、XeFM ではなく Python インタープリターの汎用アイコンと名前が表示されます。
- **不便です。** XeFM を使っている間ずっとターミナルを開いておく必要があり、そのターミナルを閉じるとウィンドウも一緒に閉じることがあります。また、Spotlight、Launchpad、スタートメニューにクリックできる項目がありません。

ソースのチェックアウトから XeFM そのものを開発するときは、`--backend gui` がやはり適切な方法です。編集のたびにアプリバンドルを作り直していては時間がかかりすぎるからです。

```bash
python3 -m xefm --backend gui   # from a checkout
make run-gui                    # the same thing, through .venv
```

### デスクトップアプリのパッケージのインストール

| プラットフォーム | インストール方法 | 署名 |
|---|---|---|
| Windows 10/11 x64 | **[Microsoft Store](https://apps.microsoft.com/detail/9PK2X44W810V)**（推奨） | あり — Microsoft による署名 |
| Windows 10/11 x64 | `XeFM-<version>-win64.zip`（ポータブル版の代替手段） | なし — [一度だけブロックの解除](#windows--ポータブル-zip)が必要 |
| macOS 12+（Apple Silicon） | `XeFM-<version>-macos.dmg` | あり — Apple Developer ID |
| macOS 12+（Apple Silicon） | [Homebrew](#macos--homebrew)：`brew install --cask crftwr/tap/xefm`（中身は同じ DMG） | あり — Apple Developer ID |

安定版のリリースには、すぐに実行できる DMG と zip が添付されます。ただし、1 つのプラットフォームの修正だけを含むリリースにはそのプラットフォームのビルドしか添付されないことがあるので、最新の zip や DMG がそれより前のタグにある場合があります。[最新リリースのリンク](https://github.com/crftwr/xefm/releases/latest)は、常に最新の安定版リリースを指します。特定のリリースに直接リンクすることもできます（例：`https://github.com/crftwr/xefm/releases/tag/v1.0.1`）。

#### Windows — Microsoft Store のパッケージ

**[Store のページ](https://apps.microsoft.com/detail/9PK2X44W810V)** から、またはシェルからインストールします。

```powershell
winget install --id 9PK2X44W810V --source msstore
```

Store のパッケージは認定の過程で Microsoft が署名するので、SmartScreen の警告は出ません。スタートメニューに登録され、Store を通じて自動で更新され、*設定 → アプリ* からアンインストールできます。設定は `%USERPROFILE%\.xefm\` に保存されて、ほかの方法でインストールした XeFM とも共有され、そのフォルダーを自分で削除しない限りアンインストール後も残ります。

#### macOS — DMG

1. リリースのページから `XeFM-<version>-macos.dmg` をダウンロードします。
2. ダブルクリックして、**XeFM** を *アプリケーション* のショートカットにドラッグします。
3. ディスクイメージを取り出し、Launchpad か Spotlight から **XeFM** を起動します。

アプリは作者の Apple Developer ID で署名されているので、Gatekeeper は普通に開きます。もし macOS が *「開発元を検証できないため、XeFM を開けません」* と表示して開かない場合（普通でない経路でダウンロードして quarantine 属性が残ったときに起こります）は、*アプリケーション* のアプリを右クリックして **開く** を選び、確認してください。以後はずっと許可されます。

削除するには、`XeFM.app` をゴミ箱にドラッグします。設定は `~/.xefm/` にあり、別に削除できます。

#### macOS — Homebrew

```bash
brew install --cask crftwr/tap/xefm
```

これで同じ公証済みの DMG が *アプリケーション* にインストールされ、`brew upgrade --cask xefm` で新しいリリースごとに更新できます。すでに DMG から手動でインストールしている場合は、`--adopt` を付けてください。Homebrew が上書きを拒否する代わりに、そのコピーを管理下に置きます。`brew uninstall --cask xefm` でアプリが削除されます。ターミナルアプリも `~/.xefm/` を読むので、`--zap` を付けてもこのフォルダーは残ります。

cask がインストールするのはデスクトップアプリだけです。`--cask` を付けない formula の `brew install crftwr/tap/xefm` はターミナルアプリです。[モードの切り替え](#モードの切り替え)を参照してください。

#### Windows — ポータブル zip

zip は Store からのインストールに代わる手段で、インストーラーではなく**ポータブルなフォルダー**です。展開して `XeFM.exe` を実行するだけです。MSI はなく、レジストリには何も書き込まれず、管理者権限も必要ありません。Store を使えないマシンで使う場合や、USB メモリやネットワーク共有から実行できるコピーが欲しい場合に使ってください。

認定の過程で Microsoft が署名する Store のパッケージとは違い、GitHub Releases の zip には署名がありません。下で説明する警告はこれが原因です。

1. **最初に zip のブロックを解除します。** ダウンロードした `XeFM-<version>-win64.zip` を右クリック → **Properties**（プロパティ）→ *General*（全般）タブの下部にある **Unblock**（許可する）にチェック → **OK**。

   Windows はインターネットからダウンロードしたファイルに *Mark of the Web* を付けます。このマークが付いた zip を展開すると、中のすべてのファイルにマークがコピーされます。展開する*前に* zip のブロックを解除すれば、すべてのマークを一度に消せます。PowerShell では次のコマンドで同じことができます。

   ```powershell
   Unblock-File .\XeFM-<version>-win64.zip
   ```

2. `XeFM` フォルダーを使いやすい場所に**展開します**。
   - `%LOCALAPPDATA%\Programs\XeFM` — ユーザーごと。管理者への昇格は不要
   - `C:\Program Files\XeFM` — すべてのユーザー。管理者権限が必要

3. **`XeFM.exe` を実行します。** 手順 1 を飛ばした場合は、SmartScreen が *「Windows によって PC が保護されました」* と表示します。**More info**（詳細情報）をクリックしてから **Run anyway**（実行）をクリックしてください。この警告はダウンロードしたコピーごとに一度だけ表示され、起動のたびには出ません。

4. *省略可能：* `XeFM.exe` を右クリック → **Pin to Start**（スタートにピン留めする）／**Create shortcut**（ショートカットの作成）で、すぐに起動できるようにします。

削除するには、展開したフォルダーを削除します（設定も消したい場合は `%USERPROFILE%\.xefm\` も削除します）。

**ダウンロードできる `.msix` がないのはなぜですか？** リポジトリでは `.msix` をビルドできます（`make windows-msix`）。しかし、MSIX は署名されていないと Windows がインストールしません。署名なしのビルドは Microsoft Store に提出するためだけのもので、Microsoft が認定の過程で署名します。そのため、ダウンロードできる `.msix` を用意してもインストールできないだけです。Store 以外では、ポータブル zip がインストールできる形式です。

**署名なしのバイナリを実行したくない場合は？** **[Microsoft Store](https://apps.microsoft.com/detail/9PK2X44W810V)** からインストールするか（Store のパッケージは Microsoft が署名しています）、PyPI からインストールして（`pipx install xefm`）XeFM をターミナルモードで使ってください。

### 初回起動

XeFM をデスクトップモードで起動すると、次のようになります。
1. ネイティブのウィンドウが表示されます
2. インターフェースはターミナルモードとまったく同じです
3. キーボードショートカットはすべて同じように動作します
4. ウィンドウのサイズを変えたり、フルスクリーンにしたりできます

## 機能

### ネイティブの macOS 環境

- **サイズ変更できるウィンドウ**：ウィンドウの端をドラッグしてサイズを変更
- **フルスクリーンモード**：緑のボタンをクリックするか、macOS のフルスクリーンのショートカットを使用
- **ウィンドウの操作**：macOS 標準の最小化、最大化、閉じるボタン
- **メニューバーとの統合**：macOS ネイティブのメニューバー（フォーカスがあるとき）

### パフォーマンス上の利点

- **高品質な描画**：GPU アクセラレーションによるなめらかな描画
- **応答性の向上**：入力に即座に反応
- **なめらかなスクロール**：大きなディレクトリを移動してもちらつきや遅延なし
- **CPU 使用率の低下**：描画を GPU が担うので CPU に余裕ができる

### 表示の改善

- **True RGB カラー**：正確な色の再現
- **より良いフォント**：アンチエイリアスによる鮮明なフォント描画
- **フォントのカスタマイズ**：好みの等幅フォントを選択可能
- **画面効果と背景アニメーション**：テーマで CRT 風の効果や動く背景を追加可能（[配色](COLOR_SCHEMES_FEATURE.ja.md)を参照）


## 設定

### バックエンドの選択

インストールしたデスクトップ版のパッケージは、常にデスクトップモードで起動します。ランチャーがネイティブのバックエンドを選ぶので、引数を渡す必要も設定する必要もありません。

`--backend` フラグが意味を持つのは、Python 環境にインストールした XeFM やソースのチェックアウトから実行する場合だけです。その場合の既定はターミナルモードで、それを変える設定ファイルのキーはありません。デスクトップモードは `--backend gui`（別名 `macos`／`windows`）ですが、上の [Why not `xefm --backend gui`?](#xefm---backend-gui-ではいけないのはなぜですか) で説明した注意点があります。

### 外観のカスタマイズ

フォントの設定は `~/.xefm/config.py` にあります（デスクトップ／GUI モードでのみ有効です）。

```python
MONO_FONT_NAME = 'Menlo'   # monospaced face for aligned columns (None = bundled default)
UI_FONT_NAME  = None       # proportional face for names/labels (None = bundled/OS default)
FONT_SIZE     = 12         # point size applied to both faces (8–72)
```

ウィンドウのサイズと位置は、実行をまたいで**自動的に**記憶されます（macOS ネイティブのウィンドウ自動保存を使います）。ウィンドウの位置やサイズを指定する設定キーはありません。

### 使えるフォント

macOS でよく使われる等幅フォントは次のとおりです。

**内蔵フォント**：
- `Menlo`（既定） - Apple の既定の等幅フォント。読みやすさは抜群
- `Monaco` - 昔からある Mac の等幅フォント。やや詰まった字形
- `Courier New` - 伝統的な等幅フォント。互換性が高い

**追加のフォント**（インストールされている場合）：
- `SF Mono` - San Francisco Mono。Apple のモダンなフォント
- `Fira Code` - 合字を備えた人気のプログラミング用フォント
- `JetBrains Mono` - モダンなプログラミング用フォント。コードに最適
- `Source Code Pro` - Adobe のプログラミング用フォント
- `Hack` - ソースコード専用に設計されたフォント

インストールされているフォントを確認するには、`Font Book.app` を開き、「固定幅」（等幅）で絞り込みます。

### フォントサイズの目安

- **小**（10～12pt）：多くの内容を表示できるが、視力が必要
- **中**（13～15pt）：読みやすさと情報量のバランスが良い（推奨）
- **大**（16～20pt）：プレゼンテーションやアクセシビリティに適する
- **特大**（21～24pt）：最も読みやすいが、表示できる内容は少ない

## 使い方

### デスクトップモードの起動

Launchpad、Spotlight、Dock（macOS）、またはスタートメニューやピン留めしたショートカット（Windows）から **XeFM** を開きます。インストールしたパッケージにはフラグは必要ありません。

開発中にソースのチェックアウトから実行する場合は、`--backend` で描画方式を選びます。

```bash
# Terminal mode (the default)
python3 -m xefm

# Desktop mode — development only, see "Why not xefm --backend gui?"
python3 -m xefm --backend gui
```

### モードの切り替え

ターミナルモードは、PyPI からのインストール（`pipx install xefm`）、Homebrew の formula（`brew install crftwr/tap/xefm`）、またはソースのチェックアウトで使えます。デスクトップ版のパッケージは自己完結したアプリケーションで、PATH に `xefm` コマンドを置かないので、2 つのインストールは互いに置き換わることなく共存します。

```bash
xefm                        # terminal mode
xefm --backend tui          # the same thing, stated explicitly
```

設定、お気に入り、履歴はすべて `~/.xefm/` にあり、デスクトップアプリとターミナルモードで共有されます。


### キーボードショートカット

デスクトップモードでも、すべてのキーバインドが同じように動作します。同じキーマップだからです。デスクトップのウィンドウでは、2 つのアクション（OS のアプリでファイルを開く操作と、macOS でのテキストのコピー）に、プラットフォーム標準のキーの組み合わせがもう 1 つ割り当てられます。それ以外はすべてターミナルと共通です。`~/.xefm/config.py` の "Three cases" を参照してください。

`F1` を押せば、いつでも設定で使われているキーを確認できます。

### ウィンドウの管理

**サイズ変更**：
- ウィンドウの端や角をドラッグします
- ウィンドウの内容は自動で調整されます
- 使いやすさのため、最小サイズが決められています

**フルスクリーン**：
- タイトルバーの緑のボタンをクリックします
- または macOS のキーボードショートカット（通常は Ctrl+Cmd+F）を使います
- フルスクリーンの解除も同じ方法で行います

**複数のウィンドウ**：
- 現在、XeFM が開けるウィンドウは一度に 1 つです
- 複数のウィンドウが必要なら、複数のインスタンスを起動してください

**終了**：
- **XeFM の終了キー**（`quit` アクション。どのキーかはキーマッププリセットによって異なります。[キーマッププリセット](KEYMAP_PRESETS_FEATURE.ja.md#すべてのキーの一覧)を参照してください）と **File ▸ Quit** は、常に先に確認します。
- **プラットフォームの終了方法**では、タスク（コピー、検索など、前面でもバックグラウンドでも進捗のダイアログが出るもの）の実行中だけ確認し、それ以外のときはすぐに終了します。該当するのは次のものです。
  - ウィンドウの閉じるボタン
  - アプリケーションメニューの **Quit XeFM** と、Dock の「終了」
  - macOS の `Cmd-Q` と Windows の `Alt-F4`
- タスクの実行中にそれでも終了すると、XeFM はまずタスクを安全に停止します。どの方法で終了しても、ペインの状態は保存されます。
- `Cmd-Q` と `Alt-F4` は、どのキーマッププリセットでも動作し、閉じるボタンと同じく、ダイアログやビューアーを開いているときにも動作します。これらは `quit_app` アクションなので、`KEY_BINDINGS` で別のキーに移したり、`'quit_app': []` で無効にしたりできます。

## トラブルシューティング

### デスクトップモードが起動しない

**問題**：デスクトップモードが起動しない、またはターミナルモードで起動してしまう。

**解決方法**：
1. Windows か macOS で実行しているか確認します。Linux にはデスクトップのバックエンドがありません。
   ```bash
   uname -s  # macOS shows "Darwin"
   ```

2. macOS では、PyObjC がインストール後も残っているか確認します（PyObjC は XeFM と一緒にインストールされるので、ここで失敗する場合は環境が壊れています。XeFM をインストールし直してください）。
   ```bash
   python3 -c "import objc; print('PyObjC OK')"
   ```

3. Python のバージョンを確認します。
   ```bash
   python3 --version  # Should be 3.11 or higher
   ```

### ウィンドウが表示されない

**問題**：デスクトップモードは起動するが、ウィンドウが表示されない。

**解決方法**：
1. コンソールの出力にエラーメッセージがないか確認します
2. まずターミナルモードで XeFM が動作するか確認します。
   ```bash
   python3 -m xefm --backend tui
   ```
3. macOS のバージョンを確認します（26 以降が必要です）
4. Mac を再起動してからもう一度試します

### フォントが見つからない

**問題**：フォントが利用できないというエラーメッセージが表示される。

**解決方法**：
1. フォント名のつづりを確認します（大文字と小文字を区別します）。
   ```python
   MONO_FONT_NAME = 'Menlo'  # Correct
   MONO_FONT_NAME = 'menlo'  # Wrong - case matters
   ```

2. フォントがインストールされているか確認します。
   - `Font Book.app` を開きます
   - フォント名で検索します
   - 等幅フォントは「固定幅」のカテゴリーで確認します

3. 既定のフォントを使います。
   ```python
   MONO_FONT_NAME = 'Menlo'  # Always available on macOS
   ```

4. フォントの設定を削除して既定を使います。
   ```python
   # Comment out or remove this line
   # MONO_FONT_NAME = 'CustomFont'
   ```


### パフォーマンスの問題

**問題**：デスクトップモードの動作が遅い、または引っかかる。

**解決方法**：
1. アクティビティモニタを確認します。
   - アクティビティモニタを開きます
   - XeFM のプロセスを探します
   - CPU と GPU の使用率を確認します

2. ウィンドウのサイズを変えて小さくします（サイズは次回のために記憶されます）。

3. 別のフォントを試します。
   ```python
   MONO_FONT_NAME = 'Monaco'  # Simpler font
   ```

4. ほかのアプリケーションを閉じてリソースを空けます

5. デスクトップモードは 60 FPS で動作するはずです。そうでない場合は、次の点を確認します。
   - GPU に負荷をかけるほかのアプリケーション
   - macOS のバージョン（古いバージョンでは遅くなることがあります）
   - 使用できるシステムメモリ

### 色がおかしい

**問題**：色がターミナルモードと違って見える。

**説明**：デスクトップモードは True RGB カラーを使うので、色数の限られたターミナルモードのパレットとは違って見えることがあります。これは想定どおりの動作で、より正確な色が表示されています。

**解決方法**：
1. 設定で配色を調整します
2. **View → Theme ▸ Next Theme** でテーマを順に切り替えるか、**View → Theme** から選びます
3. デスクトップモードの色はより正確になるはずで、悪くなることはありません

### テキストの描画の問題

**問題**：テキストがぼやける、または位置がずれる。

**解決方法**：
1. 別のフォントサイズを試します。
   ```python
   FONT_SIZE = 14  # Try different sizes
   ```

2. 別のフォントを使います。
   ```python
   MONO_FONT_NAME = 'Monaco'  # Try different fonts
   ```

3. macOS のシステム環境設定で、ディスプレイの拡大縮小の設定を確認します

4. 等幅（固定幅）のフォントを使っていることを確認します

## 比較：ターミナルモードとデスクトップモード

| 項目 | ターミナルモード | デスクトップモード |
|---------|--------------|--------------|
| **プラットフォーム** | すべて（macOS、Linux、Windows） | Windows と macOS |
| **依存関係** | Python のみ | Python（macOS では PyObjC も。自動でインストールされます） |
| **ウィンドウ** | ターミナルのウィンドウ | ネイティブのデスクトップウィンドウ |
| **描画** | ターミナルによる描画 | GPU アクセラレーション |
| **パフォーマンス** | 良好 | 非常に良好（60 FPS） |
| **色** | ターミナルのパレット | True RGB |
| **フォント** | ターミナルのフォント | カスタマイズ可能 |
| **サイズ変更** | ターミナルのサイズ変更 | ネイティブのウィンドウのサイズ変更 |
| **フルスクリーン** | ターミナルのフルスクリーン | ネイティブのフルスクリーン |
| **キーボード** | 同じ | 同じ |
| **機能** | すべての機能 | すべての機能 |

## おすすめの使い方

### デスクトップモードが向いている場面

**おすすめの用途**：
- Windows と macOS での日常的な使用
- より良い見た目
- よりなめらかな動作
- フォントや色のカスタマイズ
- プレゼンテーションや画面共有

### ターミナルモードが向いている場面

**おすすめの用途**：
- SSH セッション
- リモートサーバー
- デスクトップのバックエンドがない Linux
- 依存関係を最小限にしたい場合
- ターミナル中心の作業との連携

### 使い分けの方法

**柔軟な使い方**：
- ローカルの作業にはデスクトップモードを使う
- リモートの作業にはターミナルモードを使う
- 両方を使えるようにしておく

**実行ごとに選ぶ**：デスクトップモードではインストールした **XeFM** アプリを開き、ターミナルモードではターミナルで `xefm` を実行します。2 つは共存し、`~/.xefm/` を共有するので、切り替える操作は何もありません。作業に合うほうを選んでください。

## 高度なトピック

### macOS との統合

デスクトップとの統合は、`XeFM.app` をインストールすることで機能します。すべてアプリバンドルによるもので、ランチャースクリプトや Automator のラッパーは必要ありません。

- **Dock**：XeFM 専用のアイコン、右クリックのメニュー、*Dock に追加*
- **Cmd+Tab**：XeFM が自分の名前とアイコンで表示される
- **Spotlight／Launchpad**：「XeFM」で検索でき、キー 1 つで起動できる
- **プライバシーのアクセス権限**：デスクトップ、書類、ダウンロード、フルディスクアクセスの要求が XeFM 自身のものとして扱われ、*システム設定 → プライバシーとセキュリティ* で一度許可すれば済む

このガイドの古い版では、Dock や Spotlight に項目を作るために、`python3 -m xefm --backend gui` をシェルスクリプトや Automator のアプリケーションで包む方法を紹介していました。その方法は使わないでください。それこそが、[Why not `xefm --backend gui`?](#xefm---backend-gui-ではいけないのはなぜですか) で説明した、Python の汎用アイコンが表示されたり、アクセス権限の確認が別のアプリのものとして扱われたりする構成です。代わりに `.app` をインストールしてください。

### 起動時のディレクトリ

パッケージ版のアプリはコマンドラインの引数を取りません。ランチャーはネイティブのバックエンドで XeFM を起動するだけなので、`--left`／`--right` はコマンドラインから実行するときにしか使えません。

コマンドラインでも、これらが必要になることはあまりありません。各ペインのディレクトリは終了時に `~/.xefm/state.db` に保存され、次の起動時に復元されるので、デスクトップアプリは前回の続きから開きます。別の場所に移動するには、お気に入りのダイアログ（**Go → Go to Favorite…**）を使ってください。
