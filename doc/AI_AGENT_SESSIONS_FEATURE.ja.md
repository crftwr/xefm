# AI エージェントのセッション

[English](AI_AGENT_SESSIONS_FEATURE.md) \| 日本語

XeFM は、ファイルマネージャーの隣で AI コーディングエージェントを専用の画面に開けます。Claude Code、Codex、Copilot、Antigravity なら [XeFM が描く会話](#xefm-が描く会話)として、ほかのエージェントなら（またはそうしたければ）エージェント自身の画面を動かす[ターミナルセッション](TERMINAL_FEATURE.ja.md)として開きます。エージェントは自分が XeFM の中で動いていることを知っていて、あなたが見ているものを読み、XeFM が開ける場所ならどこでも検索し、見つけたものを見せ、ファイルを変える前にあなたに確認します。

| アクション | メニュー |
|--------|------|
| `agent` | Tools → AI Agent |
| `new_agent` | Tools → New AI Agent Here |
| `ask_agent` | Tools → Ask AI Agent… |

`agent` はどのキーマッププリセットでも `>` です（エージェントのコマンドラインが出すプロンプトの記号）。`new_agent` と `ask_agent` は既定ではキーが割り当てられていません。変えるには[キーバインド](KEY_BINDINGS_FEATURE.ja.md)と[キーマッププリセット](KEYMAP_PRESETS_FEATURE.ja.md)を参照してください。

## 必要なもの

エージェントのコマンドラインプログラムです。インストールとサインインは、それぞれ自分で済ませておきます。XeFM はエディターを起動するのと同じようにそれを起動するだけで、アカウント、認証情報、モデルには触れません。Claude Code（`claude`）、Codex（`codex`）、GitHub Copilot CLI（`copilot`）、Antigravity CLI（`agy`。Gemini CLI の後継）は最初から設定されています。ほかのエージェントは wiki にあります（[ほかのエージェント](#ほかのエージェント)を参照）。

## セッションを開く

- **AI Agent**（`agent`）は、最後に使ったエージェントのセッションに戻ります。開いているものがなければ、アクティブなペインのディレクトリでエージェントを起動します。何でも尋ねてかまいません。「このファイル」「これら」と言えば、エージェントは XeFM が表示しているものを読みます。
- **New AI Agent Here**（`new_agent`）は、セッションが開いていても、アクティブなペインのディレクトリで別のセッションを起動します。
- **Ask AI Agent…**（`ask_agent`）は、まず依頼を尋ねます（[登録した依頼](#登録した依頼agent_prompts)から選ぶか、打ち込みます）。そして、その依頼とディレクトリ、選択項目（なければカーソル位置の項目）を添えてエージェントを起動します。

`AGENTS` のエージェントが 1 つもインストールされていない（プログラムが `PATH` にない）間は、これらはメニューで無効になります。キーやコマンドパレットから使うと、どのプログラムが見つからないかをログペインに表示します。インストールすれば、再起動しなくても使えるようになります。

エージェントのセッションを使わないようにするには、`config.py` に `AGENTS = []` と書きます。これらの項目がメニューから消え、エージェントは起動しなくなり、`agent`、`new_agent`、`ask_agent` はエージェントがオフになっていることをログペインに表示するだけになります。`>` キーも空けるには、`agent` の割り当てを外してください（[キーバインド](KEY_BINDINGS_FEATURE.ja.md)を参照）。

エージェントが複数設定されていれば、XeFM はどれを使うかを尋ねます。**Screens…** にも、**New shell in ~/...** の隣に、エージェントごとの行（**New Claude Code in ~/...**）があります。セッションには、ほかのターミナルセッションと同じく専用の画面がつき、離れている間もエージェントは動き続けます。AI エージェントのセッションは、ターミナルのものとは別の 1 つのグループです。`agent` でそこに戻り、**Switch Screen** でファイルマネージャーとの間を行き来します。2 つ以上開いていると、上端にタブが並びます（[ターミナル](TERMINAL_FEATURE.ja.md#デスクトップアプリではターミナルセッションと画面)を参照）。

### セッションごとの名前

セッションには、その内容から名前が付きます。一覧を見れば、どれに戻ればよいか、どれを閉じてよいかがすぐにわかります。最初のターンが終わると、エージェントが会話にタイトルを付けていればそれを、なければ最初の依頼の先頭（**Fix the login bug**）を名前にします。ターミナルセッションで動くエージェントでは、エージェントが設定したタイトルのうち、自分の名前以上のことを言っている最初のものが名前になります。名前はその後変わりません。セッションのタブと **Screens…** の行に表示され、変えられるのはあなただけです（**Screens…** の名前の変更キー `rename_list_item`）。エージェントが今していることは、その横に表示されます。

### 閉じても失わない

閉じた [XeFM が描く会話](#xefm-が描く会話)は保存され、**Screens…** のセッションの下に **Resume Fix the login bug - ~/src** のように、エージェントと閉じた時刻とともに表示されます。選ぶと、そのフォルダーでエージェントをその会話のまま起動し直します。同じ実行中に閉じたものはやり取りの表示ごと戻り、以前の実行で閉じたものは表示が空のまま会話を続けます（残りはエージェントが持っています）。削除キーで一覧から消せます。最後の 20 件が保存されます。

そのため、ターンの途中でないエージェントは確認なしで閉じます。`/exit`、`terminal.close`、空のメッセージでの `Ctrl-D`、**Screens…** の削除キー、そこにある **Close N idle sessions** のどれでも、すぐに閉じます。ターミナルセッションで動くエージェントはエージェント自身のプログラムなので、XeFM はその会話に戻せません。こちらを閉じるときは、これまでどおり先に確認します。

ターミナルセッションで動くエージェントには、ターミナルモードでは XeFM がサブシェルと同じくターミナルを渡して待ちます。そこでエージェントが動いている間、XeFM はペインについての問い合わせと検索には答えますが、エージェントに何かを見せたり、あなたに何かを尋ねたりはできません。それにはデスクトップアプリか、[XeFM が描く会話](#xefm-が描く会話)が必要です。後者なら、ターミナルモードでも XeFM が画面を持ち続けます。

## XeFM が描く会話

Claude Code、Codex、Copilot、Antigravity（`preset` のあるエージェント）では、エージェント自身の画面をターミナルで動かすのではなく、XeFM が会話そのものを専用の画面に描きます。どのエージェントでも、見た目も動きもデスクトップアプリとターミナルモードで同じです。ターミナルモードでもエージェントがターミナルを引き取らないので、エージェントがあなたに何かを見せることも、XeFM があなたに何かを尋ねることもできます。プリセットのないエージェントはターミナルセッションで動きます。エージェントごとの違いは[下](#エージェントごとの違い)にまとめてあります。

代わりにエージェント自身の画面をターミナルセッションで使うには、エントリに `'terminal': True` を付けます。

```python
AGENTS = [
    {'name': 'Claude Code', 'command': ['claude'], 'preset': 'claude-code', 'terminal': True},
]
```

画面の上にはエージェント、そのフォルダー、エージェントがしていることが、中央には会話が、下には入力欄があります。あなたが書いたものはパネルの上に表示され、そのあとにエージェントの各ステップがドット付きで続きます（緑は成功したツール、赤は失敗したか拒否したツール）。ツールはそれぞれ 1 行で表示され（ファイル、パターン）、返した内容の最初の数行が続きます。その下の **… more lines** で残りを表示し、**show less** でまた畳みます。シェルのコマンドとその出力は、ターミナルと同じように 1 つのブロックで表示されます。編集は変更の最初の数行を表示し、**open diff** で差分ビューアーにファイル全体（編集前と現在）を開きます。続けて並ぶステップのドットは細い線でつながります。

- **サブエージェント。** サブエージェント自身のステップは、それを始めたステップの下に 1 行ずつ表示されます。表示されるのは最新のいくつかで、**… earlier steps** で残りを開きます。動いている間は、サブエージェントが今していることも表示されます。
- **思考。** **Thought ›** で、エージェントが答える前に考えた内容を開きます。エージェントがその文章を送ってきたときだけです（Claude Code は考えたことだけを送ってくることがよくあります）。
- **ToDo リスト。** エージェントが ToDo リストに沿って作業している間、リストは入力欄の上に表示され続けます。表示されるのは作業中のステップとそれ以降で、終わったものは数だけが出ます。すべて終わると消えます。
- **モデルとコンテキスト。** ヘッダーには、モデルと、会話のコンテキストがどれだけ埋まっているかが表示されます。`/model` でセッションが使えるモデルが一覧され、選ぶとそのモデルに切り替わります。エージェントを起動し直しても、選んだモデルのままです。モデルがどれだけ深く考えるかを設定できるエージェントでは、`/effort` で設定します。

| キー | 動作 |
|---|---|
| `Enter` | メッセージを送る。エージェントが作業中に送ったものは、その作業が終わるまで待つ |
| `Alt+Enter`、`Shift+Enter`、`Ctrl+J` | メッセージの中で改行する（ターミナルは `Shift+Enter` を送れません。ほかの 2 つはどこでも使えます） |
| `Esc` | 作業中ならエージェントを止める。そうでなければセッションを残したままファイルマネージャーに戻る |
| `↑` / `↓` | 入力欄の最初（最後）の行で：前に（後に）送ったメッセージ |
| `PageUp` / `PageDown` | 会話をスクロールする（ホイールでも可） |
| `Shift+Tab` | 次の権限モードに切り替える：ツールの前に尋ねる、編集を受け入れる（ファイルの変更は尋ねずに進む）、計画（エージェントは調べて計画するだけで、何も変えない）。モードはヘッダーに表示されます |

**コマンドとファイル。** メッセージの先頭で `/` と打つと、セッションのコマンド（XeFM 自身のものと、`/compact`、あなたのスキルなどエージェントのもの）が一覧され、打つほど絞り込まれます。`@` と打つとファイルを指定できます。ペインで選択中のファイル（なければカーソル位置のもの）が先頭に、続いてフォルダー内のファイルとフォルダー、さらに下の階層のファイルが名前で並びます。`↑` / `↓` で選び、`Tab` で選んだものを入れます。`Enter` でも入り、引数の要らないコマンドならそのまま実行します。`Esc` で一覧を閉じます。`/clear` と打つと新しい会話を始め、`/model` と打つとモデルを切り替え、`/exit` と打つとセッションを終えます。Claude Code 自身のコマンドは Claude Code と同じように動きます。`/usage` で使用量を表示し、`/effort` と `/fast` でエフォートと高速モードを設定します。その返答は書かれたとおりの行で表示され、Claude Code がそれとは別に知らせてくること（高速モードがオフになった、など）も会話に表示されます。設定したエフォートと高速モードは、エージェントを起動し直しても保たれます。

- **エージェントは XeFM で尋ねます。** あなたの許可が要るツールをエージェントが使おうとすると、XeFM が尋ねます。**Allow**、**Always Allow**（このセッションの残りの間許可します。設定には何も書きません。エージェントがその選択肢を出したときだけ）、**Deny** のどれかを選びます。質問には、コマンドの全体か、編集で変わる行と、**Always Allow** で何が許可されるかがエージェントの言葉で表示されます。`Bash(ssh:*)` のような規則は、目の前の 1 つのコマンドより広い範囲に及ぶことがあります。エージェントがそれを示さないときは、質問にそう表示されます。エージェントのサンドボックスを切って実行する要求や、サンドボックスの外に及ぶ要求には、エージェントがそれを XeFM に伝えたとき、**Outside the sandbox** と表示されます。最初はどのボタンも選ばれていないので、入力中の Enter や Space が答えになることはありません。左右の矢印キーで選んで Enter を押すか、ボタンをクリックします。Esc を押すと拒否します。エージェントが選択肢から選ぶよう求めたときは、XeFM が質問ごとに選択肢（1 つ選ぶもの、または複数選べるときはチェックボックス）と、自分で答えを書ける欄を表示します。[エージェントにできないこと](#エージェントにできないこと)の確認は、ほかのエージェントのセッションと同じくかかります。
- **計画。** 計画モードでは、Claude Code と Codex は最後に計画を示して承認を求めます。**Approve**（いつもどおりツールの前に尋ねながら進む）、**Approve, Accept Edits**（以後ファイルの変更は尋ねずに進む）、**Keep Planning** のどれかを選びます。ここでも最初はどのボタンも選ばれておらず、Esc を押すと計画を続けます。
- **セッションに戻る。** **AI Agent** は最後に使ったセッションに戻ります。**Ask AI Agent…** は、新しく起動せずに、そのフォルダーですでに開いているセッションに依頼を送ります。**Screens…** には、ターミナルモードを含めてこれらが表示されます。離れている間にエージェントが何か尋ねたり作業を終えたりすると、ステータスバーに表示されます。
- **リンク。** エージェントの返答の中の、このコンピューター上のファイルやフォルダーへのリンクは、アクティブなペインで開きます。
- **エージェントが止まったら**（異常終了したか、XeFM の外で終了させたとき）、会話は画面に残ります。`Enter` で同じ会話のまま起動し直します。

この機能はプレビューです。XeFM はあなた自身のプログラムを、あなたが設定したサインインのまま、ほかのプログラムから動かすためのモードで動かします。Claude Code ならストリーミング JSON（`claude -p`）、Codex なら app server（`codex app-server`）、Copilot（`copilot --acp`）と Antigravity（`agy acp`）なら [Agent Client Protocol](https://agentclientprotocol.com) です。その利用が何に数えられるかは、ターミナルで使うときと同じく、あなたとエージェントの提供元とのプランの間の話です。

### エージェントごとの違い

| | Claude Code | Codex | Copilot | Antigravity |
|---|---|---|---|---|
| `Shift+Tab` のモード | 尋ねる、編集を受け入れる、計画 | 尋ねる、編集を受け入れる、計画 | 尋ねる、計画 | 尋ねる、編集を受け入れる、計画 |
| ダイアログでの計画の承認 | あり | あり | なし：計画を書いて止まる | なし：計画を書いて止まる |
| **Always Allow** | あり | Codex がその選択肢を出したとき | あり | なし |
| 選択肢付きの質問 | あり | あり | なし：返答の中で尋ねる | あり |
| サブエージェントの下に並ぶステップ | あり | あり | なし：それぞれ別のステップとして表示される | なし |
| `/model` | 一覧から選ぶ | 一覧から選ぶ | Copilot 自身のコマンド | 一覧から選ぶ |
| `/effort` | Claude Code 自身のコマンド | あり | なし | あり |
| ほかの `/` コマンド | Claude Code のもの、あなたのスキル | `/compact`、あなたのスキル | Copilot のもの | Antigravity のもの、あなたのスキル |

- **Codex** は、あなたが設定したサンドボックスと承認の設定で動きます。モードを切り替えるまで、XeFM はどちらも変えません。**編集を受け入れる**にすると、Codex 自身の同種のモードと同じく、フォルダーへの書き込みは進め、それ以外は尋ねます。
- **Copilot** は、ツールを拒否するとその作業を止めます。代わりにしてほしいことを打ち込んでください。
- **Antigravity** は、開いたときのモードのまま始まります。*Auto* モードでは、どのコマンドを実行するかを Antigravity 自身が決め、[実行させないコマンド](#エージェントにできないこと)のうち XeFM が断れるのは、尋ねてきたものだけです。このモードで開いたときは、会話にそう表示します。XeFM がモードを変えることはありません。尋ねるモードにすると、Antigravity のサンドボックスがオフになるためです。
- エージェントへの**サインイン**は、先に XeFM の外で済ませてください。サインインしていないときは、実行すべきコマンドが会話に表示されます。
- **信頼。** Copilot と Antigravity は、自分の画面で動くときと違い、フォルダーを信頼するかどうかをここでは尋ねません。

## エージェントに渡すもの

- **`xefm` スキル**。エージェントが動いている XeFM そのものの版です。[`xefmctl`](XEFMCTL_FEATURE.ja.md) の使い方、XeFM の設定と拡張機能の仕組みが書かれています。エージェント自身のフォルダーには何もインストールしません。セッションを起動するたびにスキルを渡します。
- **[あなた自身のスキル](#自分のスキルxefmskills)**。`~/.xefm/skills/` にあるものを同じ方法で、これらのセッションにだけ渡します。
- XeFM の中で作業するための**ルール**。まず `xefmctl state` を使う、推測せずに表示されているものを読む、ファイルは `xefmctl` を通してだけ変え、変更のたびにあなたが確認できるようにする、完全には削除しない、結果は XeFM で見せる、といったものです。あなた自身のルール（`AGENT_RULES`）は XeFM のルールのあとに続きます。
- **[`xefmctl`](XEFMCTL_FEATURE.ja.md)**。このエージェントのセッションからの依頼であることを XeFM に伝える鍵が付いています。エージェントのシェルのコマンドとしても、2 つのツール `xefmctl_read`（読むだけのもの）と `xefmctl`（それ以外）としても渡します。ツールは、[エージェントのサンドボックスがコマンドを止めるところでも使えます](#エージェント自身のサンドボックス)。

## エージェントにできないこと

ルールは無視されることがあります。そこで、エージェントが何を決めても、次の 2 つは必ず守られます。

- **XeFM がすべての変更を確認します。** `xefmctl` で頼まれたコピー、移動、ゴミ箱への移動は、`CONFIRM_*` の設定でオフにしていても、その操作自身の確認ダイアログ（どのエージェントが頼んだかと、項目の一覧付き）を XeFM に出し、あなたが許可したときだけ実行されます。終わるか取り消されると、XeFM はエージェントの画面に戻ります。`xefmctl delete` は拒否され（ゴミ箱なら元に戻せます）、`delete_permanently` アクションも同様です。エージェントが `xefmctl invoke` で実行するアクションも先に確認し、削除はゴミ箱への移動になります。エージェントが指定した場所へのファイルのコピー（`xefmctl fetch`）も確認します。プログラムの実行、つまりターミナルセッションの開始（始まったセッションにはエージェントと同じ制限がかかります）、ほかのプログラムでファイルを開くこと、設定の再読み込み、あなた自身のアクションや拡張機能のアクションも確認します。エージェントがこのコンピューターのディスクの外（サーバー、クラウドストレージ、アーカイブ）のファイルを初めて読むとき、またはそこのファイルの中を検索するときは、そのセッションの間許すかどうかを XeFM が尋ねます。このコンピューターのディスクでは、エージェントが `xefmctl` でセッションのフォルダーの外のファイルを読む前に、フォルダーごとに 1 回尋ねます。あなたがペインで開いたフォルダーのすぐ下にあるファイルは尋ねません。エージェントがペインを移動させたフォルダーは、これに含まれません。これらの確認はどれも、最初はどのボタンも選ばれていません。別のことのために押した Enter で、許可したり取り消したりしてしまうことはありません。左右の矢印キーで選んで Enter を押すか、ボタンをクリックします。Esc を押すと取り消します。
- **エージェント自身のシェルを制限します。** ファイルを削除・移動するコマンド（`rm`、`rmdir`、`mv`、`unlink`、`shred`、`git clean`。Copilot と Antigravity では PowerShell の `Remove-Item`、`Move-Item`、`del` などの仲間も）を拒否するので、そうした変更は `xefmctl` を通ることになります。Claude Code と Copilot、ターミナルセッションの Antigravity は、自分の権限の設定で拒否します。こうした設定を渡せないもの（Codex と、XeFM が描く会話の Antigravity）では、エージェントがそのコマンドの実行を求めてきたときに XeFM が断ります。断れるのはエージェントが尋ねてきたものだけで、エージェント自身のサンドボックスや設定が尋ねずに通したコマンドは止まりません。ターミナルセッションの Codex にはこの制限がありません。XeFM の外と同じく、Codex 自身のサンドボックスと承認の設定で決まります。

ファイルを任せられるエージェントでこの 2 つを外すには、そのエントリに `'restrict': False` を設定します。

## エージェント自身のサンドボックス

エージェントの中には、シェルのコマンドを OS のサンドボックスの中で実行できるものがあります。エージェントが何を決めても、コマンドの届く範囲が制限されます。たいていは、書き込めるのはセッションのフォルダーだけで、ネットワークは使えません。これはエージェントの設定であり、あなたのものです。XeFM がオンにしたり、オフにしたり、緩めたりすることはありません。

- **今の状態。** XeFM が描く会話のヘッダーに、*sandbox on*（オン）、*off*（オフ）、*not known*（不明）のどれかを表示します。エージェントのセッションでの `xefmctl state` でも同じです。*not known* は、エージェントの設定しだいだということです。XeFM はその設定を読みません。
- **サンドボックスの中の `xefmctl`。** たいていのサンドボックスは、エージェントのシェルから XeFM に届かないようにします。そこで XeFM は、どのセッションにも、エージェント自身がサンドボックスの外で呼ぶ 2 つのツールを渡します。同じコマンドを、同じ制限の下で実行します。エージェントがシェルでコマンドを使おうとすると、代わりにツールを使うようメッセージで伝えます。
- **ツールの仕組み。** XeFM の中の MCP サーバーで、このコンピューターの中だけで待ち受けます。セッションごとに作るトークンがなければ何も答えず、トークンはセッションとともに無効になります。同じコンピューターのほかのユーザーはポートに届きますが、トークンなしでは使えません。エージェントの設定で閉じている場合（Copilot の `allowLocalNetwork`）、ツールは使えません。
- **確認。** Claude Code、Codex、Copilot の会話を XeFM が描くときは、XeFM のツールを呼ぶことをエージェントは尋ねません。必要なところで XeFM が尋ねます。Antigravity は先に尋ねます。自分の画面で動くエージェントも同じです。

## エージェントの設定：`AGENTS`

```python
AGENTS = [
    {'name': 'Claude Code', 'command': ['claude'], 'preset': 'claude-code'},
    {'name': 'Codex', 'command': ['codex'], 'preset': 'codex'},
    {'name': 'Copilot', 'command': ['copilot'], 'preset': 'copilot'},
    {'name': 'Antigravity', 'command': ['agy'], 'preset': 'antigravity'},
]

# Your own rules, added after XeFM's in every session.
AGENT_RULES = "Never touch ~/Documents/Taxes. Answer in Japanese."
```

| キー | 内容 |
|---|---|
| `name` | メニューと画面の一覧での名前 |
| `command` | プログラムとその引数のリスト（またはシェルと同じように分割される文字列） |
| `preset` | `'claude-code'`：スキル、ルール、権限の設定を Claude Code に渡す引数を XeFM が加える。`'codex'`：XeFM が Codex にルールを渡し、そのルールでスキルの場所を伝える。`'copilot'`：スキル、ルール、実行させないコマンドを XeFM が GitHub Copilot CLI に渡す。`'antigravity'`：スキル、ルール、権限の設定を XeFM が Antigravity CLI に渡す |
| `restrict` | `True`（既定）：上の制限をかける。`False`：かけない |
| `settings` | Claude Code と Antigravity：XeFM の設定の代わりに渡す設定。そのエージェント自身の書式で書く。例：Claude Code なら `{'permissions': {'deny': ['Bash(rm:*)']}}`、Antigravity なら `{'permissions': {'deny': ['command(rm)']}}`。XeFM が描く会話では、Antigravity のものは拒否するコマンドだけが使われる |
| `env` | 追加の環境変数 |
| `prompt_args` | プリセットなしの場合：`ask_agent` が依頼のために加えるもの（既定は `['{prompt}']`） |
| `terminal` | `True`：ターミナルセッションで、エージェント自身の画面を使う。`False`：[XeFM が描く会話](#xefm-が描く会話)。既定は `preset` があれば `False`、なければ（XeFM が描けないので）`True` |

エージェントにほかのオプションを渡すには、`command` に加えます：`['claude', '--model', 'opus']`。XeFM が描く会話には、Codex の `--model`、`--sandbox`、`--ask-for-approval`、`--profile`、`-c` と、Antigravity の `--model`、`--mode`、`--effort` が渡ります。自分の画面のためのオプションは、そこでは効きません。

`codex` プリセットはセッションの間 Codex の `developer_instructions` を設定するので、`~/.codex/config.toml` に書いたものはそこでは使われません。どのセッションにも伝えたいことは `AGENT_RULES`（または Codex 自身の `AGENTS.md`）に書いてください。

ターミナルセッションでは、Copilot と Antigravity は、あるフォルダーで初めて起動したときに、そのフォルダーを信頼するかどうかを尋ねます。セッションの中で答えてください。Antigravity は、シェルのコマンドを、あなたのフォルダーではなく、XeFM が規則を置いたフォルダーで実行することがあります。XeFM は、どのフォルダーがあなたのものかを Antigravity に伝えます。XeFM が描く会話では、これは起きません。

`config.py` に自分の `AGENTS` がある場合は、そちらが使われます。Codex、Copilot、Antigravity を使うには、その中にその行を加えてください。

### 自分のスキル：`~/.xefm/skills/`

`~/.xefm/skills/<name>/SKILL.md` に置いたスキルは、XeFM が起動するすべてのエージェントのセッションに渡り、ほかの場所で動かすエージェントには渡りません。ファイルマネージャーのそばでだけ意味のあることに使います。`xefmctl` を使った作業の手順、写真の並べ方や名前の付け方、ダウンロードしたものの置き場所などです。エージェント自身のスキルフォルダーに置くと、同じ指示がコーディングのセッションにも毎回出てきます。

いちばん簡単な作り方は、セッションの中で頼むことです。

> Write a skill that sorts photos into year/month folders by date taken, and
> install it as an XeFM skill.

エージェントがフォルダーを書き、チェックします。スキルはふつうの [Agent Skills](https://agentskills.io) のフォルダーです。フォルダー名と同じ `name` と、いつ使うかを書いた `description` を持つ `SKILL.md` と、その横に置くファイルからなります。手で書くことも、ほかからコピーしてくることもできます。

- 新しいスキルや変更したスキルは、**次の**セッションから使われます。設定の再読み込みはいりません。スキルを書いたセッションですぐ使いたいときは、そのセッションが直接読みます。
- Claude Code では `xefm-user:<name>` として出てきて、XeFM 自身の `xefm:xefm` とは分かれます。プリセットのあるエージェントにはすべて渡ります。ターミナルセッションの Codex には、ルールの中で各スキルとその場所を伝えます。
- `xefmctl skill list` は自分のスキルと、それがセッションに渡るかどうかを表示します。`xefmctl skill check <name>` は、スキルの問題を表示します。この 2 つは、XeFM をどの方法でインストールしても、どのセッションでも使えます。`xefm` が PATH にある場合（pip や Homebrew でインストールした場合）は、どのシェルからでも `xefm skills list|check` で同じことができます。チェックに通らないスキルは渡しません（ログに警告が出ます）。`xefm` という名前は XeFM 自身のスキルが使っています。
- 削除するには、そのフォルダーをゴミ箱に移します。

### 登録した依頼：`AGENT_PROMPTS`

よく頼むことを登録しておくと、**Ask AI Agent…** に一覧で出ます。選ぶか、自分で打ち込みます。エージェントにはディレクトリと選択項目も渡るので、「these files」はあなたが選んだものを指します。

```python
AGENT_PROMPTS = {
    'Summarize': 'Summarize these files, a few lines each.',
    'Sort photos by month': 'Move these photos into folders named YYYY-MM by the date taken.',
    'Review': {'prompt': 'Review the uncommitted changes here.', 'agent': 'Claude Code'},
}
```

依頼は文字列か、`prompt` と `agent`（`AGENTS` のエントリの `name`。指定すると、尋ねずにそのエージェントに送ります）を持つテーブルです。設定のテンプレートには、ほかの例がコメントアウトした状態で入っています。[拡張パッケージ](EXTENSIONS_FEATURE.ja.md)も依頼を追加できます（`[contributes.agent_prompts]`）。`AGENT_PROMPTS` はプレビューです。

### ほかのエージェント

プリセットのないエージェントには、`command`（と `prompt_args`）の中のプレースホルダーを通して必要なものを渡します。XeFM はセッションを起動するときにそれを埋めます。

| プレースホルダー | 置き換わるもの |
|---|---|
| `{skills_dir}` | `xefm` スキル（`xefm/SKILL.md`）を入れたスキルフォルダー |
| `{skill_dir}` | `xefm` スキル自体のフォルダー |
| `{plugin_dir}` | 同じスキルを Claude Code のプラグインとして入れたフォルダー |
| `{user_skills_dir}` | [自分のスキル](#自分のスキルxefmskills)を入れたスキルフォルダー（スキルがなければ空） |
| `{user_plugin_dir}` | 同じものを Claude Code のプラグイン（`xefm-user`）として入れたフォルダー |
| `{rules}` / `{rules_file}` | ルールのテキスト / ルールを書いた Markdown ファイル |
| `{settings_file}` | 指定した `settings` の JSON ファイル（指定がなければ空） |
| `{mcp_config_file}` | [XeFM のツール](#エージェント自身のサンドボックス)を書いた MCP の設定（`mcpServers`、HTTP）の JSON ファイル。ツールを用意できなかったときは空 |
| `{prompt}` | `ask_agent` の依頼 |

これらをどう受け取るかはエージェントごとに違います。wiki のページ [AI agents](https://github.com/crftwr/xefm/wiki/AI-agents) に、ほかのエージェントのエントリを、それを使っている人たちが書いて保守しています。`xefmctl` への XeFM 自身の制限は、どのエージェントにもかかります。
