# AI エージェント向け XeFM スキル

[English](AGENT_SKILL_FEATURE.md) \| 日本語

XeFM は [Agent Skills](https://agentskills.io) 形式のスキル **`xefm`** を提供しています。AI エージェントがあなたに代わって XeFM を扱えるようにするためのものです。扱う範囲は次の 2 つです。

- **設定の編集**（`~/.xefm/config.py`）：キーバインドとキーマッププリセット、エディターと差分ツール、お気に入り、ファイルの関連付け、外部プログラム、テーマ、自作の小さなアクション。エージェントは頼まれたところだけを変更し、ファイルのそれ以外の部分はそのまま残します。
- **[拡張パッケージ](EXTENSIONS_FEATURE.ja.md)の作成**：マニフェスト、拡張機能が使ってよい API、設定項目、依存関係、テスト。最後のステップは `xefm ext check` で、パッケージが拡張機能のすべての要件を満たしていることを確認します。

スキルは `SKILL.md` ファイルと 2 つのリファレンスファイルが入ったフォルダーなので、Agent Skills を読めるエージェントならどれでも使えます。

## いちばん簡単な方法：エージェントにインストールさせる

このページをエージェントに渡して、スキルのインストールを頼みます。たとえば次のようにします。

> Install the XeFM skill by following
> https://crftwr.github.io/xefm/doc/AGENT_SKILL_FEATURE.html

エージェントは下の [AI エージェント向けの手順](#ai-エージェント向けの手順)に従います。スキルをどこに置いたかの報告があったら、そのエージェントで新しいセッションを始めてください（ほとんどのエージェントはセッション開始時にスキルを読み込みます）。あとはやりたいことを頼むだけです。たとえば「XeFM で F12 に設定の再読み込みを割り当てて」や「…する XeFM の拡張機能を作って」のようにします。

エージェントが XeFM を自分で起動することはありません。設定を変更したときは、**Tools ▸ Reload Configuration**（設定の再読み込み）を実行するように（再起動が必要な一部の設定項目の場合は XeFM を再起動するように）伝えてきます。

## 自分でインストールする

1. [XeFM のリリースページ](https://github.com/crftwr/xefm/releases)から、使っている XeFM（`xefm --version` または **Help ▸ About** で確認できます）に対応するリリースの **`xefm-X.Y.Z-skill.zip`** をダウンロードします。
2. それをエージェントのスキルフォルダーに展開します。zip には `xefm/` というフォルダーが 1 つだけ入っており、これがスキルフォルダーの直下に来るようにします。

   ```
   <skills folder>/xefm/SKILL.md
   ```

   使うスキルフォルダーは次のとおりです。

   | エージェント | すべてのプロジェクトで使うスキルフォルダー |
   |---|---|
   | Agent Skills を読むほとんどのエージェント | `~/.agents/skills/` |
   | Claude Code | `~/.claude/skills/` |
   | その他 | そのエージェント独自のスキルフォルダー（各エージェントのドキュメントを参照） |

   1 つのプロジェクトだけでスキルを使う場合は、そのプロジェクトの中に同じ名前のフォルダーを使います。たとえば `<project>/.agents/skills/` です。
3. そのフォルダーに **`xefm-extension-authoring/`** もある場合は削除します。これはこのスキルの古い、拡張機能専用の版（XeFM 1.8.0 以前）で、同じ役割のスキルが 2 つあるとエージェントが混乱します。
4. エージェントで新しいセッションを始めます。

`xefm` が PATH にある場合（pip、pipx、uv、Homebrew でインストールした場合）、スキルはすでにマシン上にあります。`xefm skill` でその場所が表示され、次のコマンドでスキルフォルダーにコピーできます。古い `xefm-extension-authoring/` があれば、それも削除されます。

```bash
xefm skill --install ~/.agents/skills
```

## 更新

スキルが説明しているのは、ある 1 つの XeFM バージョンの設定と拡張機能 API です。XeFM をアップグレードしたら、対応するリリースからスキルをインストールし直してください。古い `xefm/` フォルダーの上に展開するのではなく、フォルダーごと置き換えます。

インストール済みのスキルがどの XeFM について書かれたものかは、その `SKILL.md` の先頭近くにある `xefm-version` の行で確認できます。`+dev` を含むバージョン（たとえば `1.9.0+dev.g1a2b3c4d5`）は、そのリリースより新しい未リリースのソースから作られたものです。`g` の後ろはコミットを表し、末尾の `.dirty` はソースにコミットされていない変更があったことを表します。スキルを使うエージェントは、これを自分で `xefm --version` と照合し、異なっていれば一度だけそのことを伝えます。

## AI エージェント向けの手順

あなたは `xefm` スキルのインストールを頼まれています。次の手順に正確に従ってください。zip に入っているのは Markdown だけなので、中のものを実行する必要はありません。

1. **バージョンを決めます。**
   - `xefm` が PATH にあれば、`xefm --version` を実行します。`XeFM X.Y.Z` と表示されるので、`X.Y.Z` を使います。
   - そうでなければ、最新リリースのタグを調べます。`https://api.github.com/repos/crftwr/xefm/releases/latest` から `tag_name` を読みます（または `gh release view --repo crftwr/xefm --json tagName` を実行します）。値は `vX.Y.Z` なので、`X.Y.Z` を使います。
2. 新しい空の一時ディレクトリに **zip を取得します。**
   - `xefm` が PATH にあれば、`xefm skill --zip <temp>/xefm-X.Y.Z-skill.zip` を優先して使います。インストール済みの XeFM に対応するものが、ダウンロードなしで書き出されます。
   - そうでなければ、`https://github.com/crftwr/xefm/releases/download/vX.Y.Z/xefm-X.Y.Z-skill.zip` をダウンロードします。404 が返る場合（XeFM がこのスキルより古い場合）は、代わりにステップ 1 の最新リリースのバージョンを使います。
3. 使う前に zip を**確認します。**
   - 最上位のフォルダーが `xefm/` 1 つだけであること。
   - `xefm/SKILL.md` が含まれていること。
   - そのファイルのフロントマターに `name: xefm` があること。

   どれか 1 つでも満たさなければ、中止してユーザーに伝えます。
4. **スキルディレクトリを選びます。** 自分自身がスキルを読み込んでいるユーザーレベルのスキルディレクトリを使います。複数から読み込んでいる場合は `~/.agents/skills/` を優先します。プロジェクトレベルにインストールするのは、ユーザーがそう頼んだときだけです。どこからスキルを読み込んでいるかわからない場合は、推測せずにユーザーに尋ねます。

   `<skills dir>/xefm/SKILL.md` がすでに存在し、そのフロントマターにステップ 1 のバージョンで `xefm-version: "X.Y.Z"` とある場合、スキルはすでに最新です。一時ディレクトリを削除し、そのことをユーザーに伝えて終了します。
5. **インストールします。**
   - `<skills dir>/xefm/` がすでに存在する場合は削除します。
   - 結果が `<skills dir>/xefm/SKILL.md` になるように zip を展開します。1 階層深くネストしていないことを確認します。
   - `<skills dir>/xefm-extension-authoring/` が存在し、その `SKILL.md` に `name: xefm-extension-authoring` とある場合は、そのフォルダーを削除します。このスキルが置き換える古いスキルです。
   - 一時ディレクトリを削除します。
6. ユーザーに次のことを**報告します。**
   - インストール先のパス
   - インストールしたバージョン
   - 古い `xefm-extension-authoring` スキルを削除したかどうか
   - スキルを読み込むには新しいセッションを始める必要があること

   ユーザーに頼まれていない限り、同じステップのまま設定の編集や拡張機能の作成を始めないでください。
